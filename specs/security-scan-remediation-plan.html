目的與完成定義

本計畫不是只消除掃描器指出的單一 sink，而是把重複出現的根因提升為共用安全契約：工作區信任、typed identifiers、descriptor-relative path confinement、operation-scoped authority、secure transport、verified provenance、pre-allocation budgets。

Release gate：Phase 1–4 的 6 項 High 在任何新版本發布前必須全部關閉；Medium 不得以「顯示警告」代替後端控制。最終必須以 hostile fixture、跨平台 packaged build 與獨立重掃證明，不以 code review 主觀判斷代替。
  • 12 項發現都有對應的 backend control、regression test、UI 行為與完成證據。
  • 所有 native security decision 在 Rust backend 執行；renderer validation 只作 UX，不作唯一防線。
  • 所有拒絕路徑為 typed / machine-readable error，UI 只顯示安全、可翻譯訊息，不洩漏 secrets。
  • 報告列出的 4 組 follow-up proof gap 必須有實測結論；若發現新漏洞，新增 finding 而非把它藏在備註。
  • 修復後 Codex Security 對相同與新增 fixtures 重掃，目標為 0 個未關閉 High / Medium。

安全架構原則

Untrusted workspace / remote peer
→
Typed validation + trust gate
→
Capability-bound backend operation
→
Native side effect / bounded IPC
Fail closed
安全 metadata 缺失、host-key store 寫入失敗、LSP digest 不存在、response 超限時，一律拒絕，不以 best-effort 繼續。
Trust is not sanitization
工作區 trust 只授權執行 repository code；即使 trusted，Git path、SFTP leaf、preview filesystem 與 response budgets 仍然必須驗證。
Backend-held authority
前端不能透過傳入 trusted=true、完整 destination path 或任意 hash 取得權限；backend 從自身 state 與 typed context 判定。
Exact user intent
預覽命令顯示原文並原樣執行，不改寫 user-defined command；但執行前必須取得 workspace trust。破壞性 Git / SFTP 操作只作用於確認的 literal object。
One capability, one operation
Askpass、preview session、SSH host-key challenge、SFTP destination 都使用短生命週期 capability，不使用 app-lifetime bearer。
Budget before allocation
限制必須在 clone、decode、row retention、JSON parse 或 DOM segment creation之前生效；事後 pop 不算完成修復。

[] Phase 1：Git literal paths 與 typed revision（F3、F6）

先關閉兩個高嚴重度、修復面較集中的 Git injection，降低實作其餘 phase 時對工作樹造成破壞的風險。

1.1 F3 — 全部 repository path 一律 literal

  • [] 在 run_git 的安全預設環境加入 GIT_LITERAL_PATHSPECS=1；只有經安全 review 的 internal pattern command 才可使用具名 escape hatch。
  • [] 清點 stage、unstage、discard、rollback、status scope、diff、file-at-rev、ls-tree 等所有 path sinks；移除散落的重複 literal env 或改為中央 helper。
  • [] 保留 -- 與 existing status-classification checks；literal pathspec 不取代 stale-state / containment 控制。
  • [] 破壞性操作後重新取得 status，驗證 changed set 沒超出請求集合；若 scope mismatch，回報安全錯誤並停止後續 mutation。

1.2 F6 — OID-first log pipeline

  • [] 新增 GitOid；只接受 repository object format 對應的完整 hex OID，不接受 ref、prefix、option 或 revision expression。
  • [] Log pagination 第一步只輸出固定格式 OID；metadata 以 git cat-file --batch 的長度 framing 讀取 commit object，解析 headers/message，而不以 commit-controlled delimiter 切 record。
  • [] Ref decoration 由 for-each-ref 建立 OID→refs map；不可讓 subject 重新塑造 hash / parents / timestamp。
  • [] 所有 renderer-supplied revision 經中央 resolve_commit_oid：rev-parse --verify --end-of-options，只把 resolved OID 傳給後續 Git。
  • [] git show / name-status / numstat argv 在 revision 前使用 end-of-options，並在 pathspec 前保留 --。
  • [] Malformed metadata 採整頁 fail-closed；不得 silently continue 丟棄可疑 record 後回傳部分偽造資料。

1.3 Testing Strategy

  • [] cd src-tauri && cargo test --locked git_service::tests — stage/unstage/discard/rollback 對 :(top)**、:(glob)**、*、?、:(exclude) 只作用 literal file。
  • [] cd src-tauri && cargo test --locked git_log::tests — delimiter subject 不產生 synthetic row；option revision 在 spawn 前拒絕；正常 merge/root/rename log 不回歸。
  • [] cd src-tauri && cargo test --locked — 中央 Git env 不破壞 branches、diff、status、file-at-rev 與 conflict flows。
🔁 只有 literal filename scope 與 typed OID 的 exploit fixtures 全通過，F3/F6 才可標記完成。

[] Phase 2：Backend Workspace Trust 與 process execution（F1）

採取最小且最強的 pre-trust policy：未信任 workspace 不執行任何 repository-aware Git、package script 或 workspace-selected native process。這比維護一份不完整的 Git executable-config blacklist 更可證明。

2.1 Trust identity 與持久化

  • [] 實作 versioned ~/.yuzora/workspace-trust.json；測試使用 temp path，不污染使用者資料。
  • [] Identity 至少綁定 workspace canonical path 與 filesystem identity（Unix dev/inode；Windows volume/file identity）；directory replacement、symlink retarget 或不可解析時使 grant 失效。
  • [] Backend 提供 status / grant / revoke；grant request 必須引用 backend 剛簽發、短生命週期的 challenge，不接受 renderer 自報 identity。
  • [] Store 寫入使用 same-directory temp、flush/fsync、atomic rename；寫入失敗不授權當次操作。

2.2 Enforce trust at sinks

  • [] git_detect / git_bootstrap 在 pre-trust 只做 filesystem-level repo presence projection，禁止 spawn Git；UI 顯示「信任後啟用 Git」。
  • [] 所有 Git commands 在 backend 共用 trust guard；不得逐 command 漏加。
  • [] dev_server_detect 可讀取 script 字串供 review，但 process_service.start 在 spawn 前重新檢查 trust challenge、canonical workspace 與 command digest。
  • [] Trust dialog 顯示 canonical workspace 與 exact command；user-defined command 保持原文，不在 Rust 端改寫。
  • [] Child process 採最小 environment allowlist；移除 app secrets、askpass token、provider credentials 等非必要繼承值。PATH 來源需明確，避免 cwd-first launcher hijack。
  • [] Revoke / identity mismatch 時停止該 workspace 由 Yuzora 啟動的 dev server，並清理 pending execution capabilities。

2.3 UI 與 i18n

  • [] 以 shadcn AlertDialog 組合 Trust Host；焦點、Escape、取消、exact command copy 與 screen-reader label 都有測試。
  • [] 新增 en / zh-TW 文案，明確區分「信任 workspace」與「只連接既有 localhost server」。後者不需執行 repo code。
  • [] 設定頁提供 trusted workspaces 列表與 revoke；UI 只投影 backend state。

2.4 Testing Strategy

  • [] Rust：untrusted fixture 的 core.fsmonitor marker 在 bootstrap 前後皆不存在；所有 Git command 回 typed UntrustedWorkspace。
  • [] Vitest：Preview Start 顯示 exact command；取消不 invoke spawn；identity change 後重新要求信任。
  • [] bun run test src/app/panels/previewPanel.test.tsx — trust、connect-existing、command override flow。
  • [] cd src-tauri && cargo test --locked workspace_trust && cargo test --locked git_service && cargo test --locked process_service — backend authorization 與持久化。
🔁 未信任 workspace 只要有任何 Git / shell 子程序可被 spawn，F1 即未完成。

[] Phase 3：Static Preview capability isolation（F2）

把「serve directory」改成「建立 selected document 的 preview session」。合法 asset availability 與 filesystem confidentiality 必須同時成立。

3.1 Session 與 resource policy

  • [] 將 preview_serve(dir) 改為 preview_create(selected_html)；backend canonicalize selected file 並建立不可預測 session token、專屬 port / origin、expiry 與 allowed-path set。
  • [] 解析 HTML 的相對 src、href、srcset、poster；遞迴解析 CSS @import / url() 與 static module imports，將 canonical-contained dependency 加入 allowlist。
  • [] 任意 requested path 不在 allowlist 即 403；一律禁止 dotfiles、VCS metadata、secret basenames / extensions、NUL、symlink escape，即使被 HTML 引用也拒絕。
  • [] 回應加入 Cache-Control: no-store、嚴格 MIME、X-Content-Type-Options: nosniff 與適用的 CSP；不回傳 filesystem path。
  • [] 同一檔案每次 preview 都取得新 token；tab close、workspace switch、app shutdown 立即 revoke；不得只靠 port 保密。

3.2 Browser isolation

  • [] Static preview iframe 移除 allow-same-origin；保留 scripts 需明確接受 module/CORS 相容性調整，且 server 不得加 wildcard CORS。
  • [] 將 static preview 與 dev-server preview 模式分開：dev server 維持 localhost URL，但不共享 static session authorization。
  • [] External child WebView 加入 navigation allowlist / external-open policy，阻止由 remote page 導向 asset/app custom protocol；相關 Tauri ACL 只授權 main window。

3.3 Testing Strategy

  • [] cd src-tauri && cargo test --locked preview_server::tests — declared assets 200；.env、.git/config、unknown sibling、traversal、symlink 均 403；expired token 404/410。
  • [] bun run test src/preview/previewFrame.test.tsx src/preview/previewCommands.test.ts src/state/previewStore.test.ts src/state/contextMenuStore.test.ts — iframe sandbox、session lifecycle、workspace switch cleanup。
  • [] Packaged macOS / Windows / Linux：惡意 static HTML 的 fetch / iframe / module / popup 不能讀取 denied bytes；合法 CSS/JS/image 仍載入。
🔁 只加 denylist 或只移除 same-origin 都不是完整修復；allowlist、origin isolation、expiry 三者需同時有證據。

[] Phase 4：SFTP path capabilities 與 SSH host trust（F4、F5、F10）

將 remote name、workspace pathname 與 authenticated host identity 從一般 String 升級為經 backend 驗證的 capability。

4.1 F4 — Symlink-aware workspace upload

  • [] FileNode 增加 kind: file | directory | symlink | other 與必要的 reparse metadata；使用 symlink_metadata，不跟隨 final link。
  • [] UI 顯示 symlink 狀態並預設停用 workspace upload；提示使用者以 explicit native picker 選擇 target，而非暗中跟隨。
  • [] Upload IPC 改為 tagged source：Workspace { root, relativePath } 或 Picker { capabilityId }；不得只傳任意 localPath。
  • [] Workspace source 透過 path_capability descriptor-relative / beneath / no-follow open；在同一已驗證 descriptor 上取得 size 並 streaming，避免 check-then-open race。
  • [] Unix 使用 openat2 RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS 或等價 fallback；Windows 使用拒絕 reparse point 的 handle semantics。無可靠實作的平台 fail closed。

4.2 F5 — Safe remote leaf 與 destination handle

  • [] 實作 backend SafeLeafName：拒絕 empty、.、..、NUL、/、\、drive/UNC/verbatim prefix 與平台 alternate separator。
  • [] SFTP listing ingestion 先驗證 leaf；transfer sink 再驗證一次。前端檢查只用於提早提示。
  • [] Download IPC 傳 destinationDirectoryCapability、validated remote leaf、overwrite mode；不再傳 renderer 拼好的完整 destination path。
  • [] Temp create、flush、replace/rename 全部相對於 pinned directory handle；temp 使用 create_new / no-follow，並在取消或錯誤時清理。
  • [] Overwrite confirmation 綁定 directory identity + leaf + existing file identity；確認後若 identity 改變，重新要求確認或拒絕。

4.3 F10 — Blocking host-key challenge

  • [] check_server_key 對 unseen key 建立 pending challenge，emit endpoint、algorithm、SHA256 fingerprint，等待 user accept/reject；在結果前不得進入 password/public-key authentication。
  • [] Challenge 有不可預測 ID、canonical endpoint、timeout、single-use semantics；renderer 不能替另一連線決定。
  • [] Accept 先完成 locked read-merge-write、file sync、atomic rename、parent sync，再回傳 true；持久化失敗 fail closed。若未來提供 session-only trust，必須為明確第二個選項。
  • [] Matching pin 靜默通過；changed pin 永遠 hard fail 並顯示 old/new fingerprint，不提供一鍵覆寫。
  • [] UI 使用 shadcn AlertDialog，支援 keyboard、copy fingerprint、取消與 timeout 狀態。

4.4 Testing Strategy

  • [] cd src-tauri && cargo test --locked ssh_service::tests && cargo test --locked fs_service::tests — symlink/reparse、malicious leaf、atomic store、concurrency、write failure。
  • [] bun run test src/app/panels/sshPanel.test.tsx src/lib/paths.test.ts — disabled symlink action、unsafe name UX、fingerprint dialog。
  • [] Packet-level fixture 證明 unseen key decision 前沒有 auth request；changed key 也沒有 credential。
  • [] macOS / Windows / Linux race fixture 在 path swap 下不能讀寫 selected directory 外。
🔁 Canonicalize-then-open 仍有 TOCTOU，不算 F4/F5 完成；必須以 pinned handle / descriptor 證明。

[] Phase 5：Askpass authority、PostgreSQL TLS、DB memory（F7、F8、F9）

同時處理 credential scope、transport confidentiality 與 hostile result allocation，確保 remote-service 邊界不再依賴安全預設或事後 accounting。

5.1 F7 — Per-operation askpass

  • [] 每次 fetch/pull/push/probe 建立獨立 random capability 與 server-side context：repository identity、remote fingerprint、operation type、foreground policy、expiry。
  • [] Token 只注入該 child environment；cache key 包含 operation ID + prompt kind，或預設不 cache。Background policy 必須在任何 cache lookup 前執行。
  • [] Child spawn 後綁定 PID / process tree；Unix 以 peer credential、Windows 以 named-pipe client identity 或等價控制驗證 caller。不能驗證的平台至少維持 one-operation unguessable token。
  • [] Child exit、timeout、cancel 時 revoke capability，喚醒 pending waiter，並以 zeroize 清除 secret/cache。
  • [] Askpass UI request 顯示 operation/repository/remote context，不只顯示 attacker-controlled prompt。

5.2 F8 — Secure PostgreSQL profile schema

  • [] 以 typed mode 取代模糊 booleans：verifyFull（default）、encryptedTrustServerCert、insecurePlaintext。
  • [] 新 profile 與缺欄位 migration 對 PostgreSQL 預設 verifyFull；既有明確 ssl=false 保留但標記 insecure exception，首次使用前要求重新確認。
  • [] Plaintext save/connect 需 explicit per-profile acknowledgement；UI 顯示 host/user/database、可被攔截的資料類型與撤銷方式。
  • [] Backend 拒絕未帶 persisted exception 的 NoTls；TLS default 驗證 certificate chain 與 hostname。trustServerCert 也必須明確警告。
  • [] Migration 不改動 SQLite/MSSQL 語意，且 credential 不出現在 log/error。

5.3 F9 — Allocation 前 budget

  • [] 定義單欄、單列、session 與 process 四層 hard ceiling；registry 暴露 remaining_budget，converter 在 clone/decode 前取得。
  • [] SQLite 對 borrowed TEXT/BLOB bytes 先檢查長度，再建立 DbValue；超限立即 interrupt。
  • [] PostgreSQL / MSSQL 使用 raw/borrowed decoder 檢查 wire value length，避免先建完整 String/Vec 再計算；一旦不足，立即 cancel 並停止 materialization。
  • [] push_row 改為 insertion 前估算 / reserve budget，移除「push → refresh → pop」安全依賴；保留 accounting assertion。
  • [] 驗證 driver 是否仍會在 Row 建立前無上限配置 protocol frame。若無可用 frame cap，將 query decode 移入具 OS memory limit 的 helper process；helper crash 轉為 typed QueryResultTooLarge，主程序保持可用。
  • [] Result DTO 回傳 limitReached 與已保留 pages；不得把超限內容送往 Tauri IPC。

[] Phase 6：Verified LSP supply chain 與 bounded Herdr（F11、F12）

6.1 F11 — Immutable LSP catalog

  • [] Catalog 每個 server/platform 綁定 exact version、asset URL、expected SHA256 或 signature key、unpack type、expected executable path；metadata 缺失即不可 install。
  • [] Binary 下載先 streaming 至 non-executable temp，同步計算 digest；驗證成功後才 unpack、chmod、atomic promote。失敗清理 temp，既有版本保持不動。
  • [] npm route 使用 repo-reviewed lockfile/integrity，staging 執行 npm ci --ignore-scripts --no-audit --no-fund；package 與 transitive dependency 都不可浮動。
  • [] pip route 使用 exact versions + --require-hashes，包含 transitive wheels；預設 --only-binary=:all:，禁止任意 build backend code。
  • [] Lifecycle/build script 若不可避免，需 catalog 明示 audited exception、版本與 rationale，並在受限環境執行；不得默默開啟。
  • [] Managed launcher 從 app-process PATH 絕對解析，拒絕 relative PATH segment 與 workspace shadowing；user-defined custom command 原樣保留但受 workspace trust。
  • [] 安裝完成寫 provenance record：catalog version、artifact digest、installed path、verified timestamp；launch 前重驗 file identity/digest 或 immutable install identity。

6.2 F12 — Bounded Herdr framing 與 rendering

  • [] 將 existing read_bounded_ndjson_line 提升為所有 event/API lanes 共用 helper；api_request 不再使用 unbounded read_line。
  • [] 1 MiB framing ceiling 在 newline/JSON parse 前生效；oversized、unterminated、invalid UTF-8 回 typed protocol error 並關閉 stream。
  • [] Response schema 對 agent text、arrays、pane counts 與 nested depth 設定 hard cap；agent text 建議 512 KiB，超限請求 server-side truncation 或拒絕。
  • [] Tauri IPC 前再次檢查 serialized byte size；不把任意 serde_json::Value 原樣 fan-out 至 renderer。
  • [] parseAnsiSegments 先限制 input bytes / code points，合併相鄰 style，限制 segment count（例如 10,000），超限顯示單一 truncation sentinel。
  • [] React render 使用穩定 key 與 bounded spans；大量 text 使用現有 ScrollArea / virtualized surface，不創造 bare overflow primitive。

決策、風險與回滾策略

優先順序與依賴

  1. Phase 1 先行：F3/F6 是集中且高破壞性的 Git input bugs，可快速降低 blast radius。
  2. Phase 2 是 execution foundation：其後所有 package script / user command 行為都依賴 backend trust。
  3. Phase 3/4 關閉其餘 High：release gate 到此才可解除。
  4. Phase 5/6 關閉 Medium：其中 F9 可能需要 helper-process architecture，不得為趕時程把驗收降級為 retained-byte test。
  5. Phase 7/8 補證據：partial scan 不可直接轉為「整個 repo 安全」。

不可採用的捷徑

  • 只在前端檢查 filename/hash/trust，再把未驗證 String 傳給 Rust。
  • 把 -- 當作 Git pathspec magic 的完整防護。
  • Preview 只 deny .env，但仍 serve whole directory / same origin。
  • SFTP 只做 canonicalize 再 open，留下 TOCTOU。
  • SSH unseen key 先連線，連線後再通知 user。
  • Askpass 只把 app-wide cache TTL 從 60 秒縮短，卻不隔離 operation。
  • DB 只在 row push 後 pop、只限制 row count、或把 ceiling 調高。
  • LSP 只顯示 computed digest、只 pin top-level package version、或信任 registry 的 current metadata。
  • Herdr 只設 timeout；持續傳送 bytes 的 peer 仍能在 timeout 前耗盡 memory。

風險與 mitigation

風險可能影響Mitigation
Workspace trust 使 Git 初次使用多一步Git panel 在 grant 前不可用清楚呈現原因；仍允許不執行 code 的 filesystem editing 與 connect-existing preview。
Static asset allowlist 不支援 dynamic fetch部分 HTML preview asset 失敗回傳可讀 blocked-resource 診斷；擴充 parser 只加入明確 dependency，不提供 whole-directory fallback。
Descriptor-relative API 跨平台差異Windows / older Linux 實作複雜集中於 path_capability.rs；無安全 primitive 時 fail closed 或使用 native picker capability。
DB driver 自身先配置巨大 frame應用仍可 OOM以 RSS fixture 決策；若無 driver cap，使用受 OS memory limit 的 helper process。
LSP pins 容易過期新版 server 無法即時安裝提供 catalog update script + review 流程；安全上寧可 fail unavailable，不可自動信任 latest。
Herdr ceiling 截斷合法大輸出使用者看不到完整內容顯示 truncation/too-large 狀態，讓使用者縮小 lines/source；不要 silently truncate。

Rollout 與 rollback

  • 每 phase 使用獨立 feature flag 只作部署控制，不得提供回到 vulnerable behavior 的使用者開關。
  • Profile / trust / provenance store 都具 schema version 與 backward-read migration；寫新格式前先備份舊檔，credential 不進備份。
  • 若 phase 發生功能回歸，rollback 到前一個安全版本；不要 rollback 單一 backend guard 而保留依賴它的新 UI。
  • DB plaintext exception、trusted workspace、SSH pin 與 LSP provenance 都應可由設定頁檢視與撤銷。
