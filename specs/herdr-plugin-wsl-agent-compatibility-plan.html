01 · Executive summary

先升 Stable，再做 Plugin-managed WSL 相容層

GO

Pi WSL live identity／state

Plugin 建立 pane、Pi adapter 經 herdr.exe pane report-agent 回報 working／idle／blocked。Yuzora 只投影 snapshot／events 既有 identity 與 state；Pi native session id 僅寫 adapter log，不進 Yuzora DTO，也不可 resume。

DEFERRED

Claude／Codex

已拍板延後。本輪不交付 Claude／Codex installer、action、adapter、test 或驗收；不得把延後項目標成 PASS。

NO-GO

透明相容任意 WSL pane

Plugin v1 無 spawn interceptor、跨 WSL process observation 或新 Agent kind；任意手動 wsl.exe pane 不列入第一版承諾。

計畫核心：在 Yuzora repo 內新增 herdr-plugins/yuzora-wsl-agents/，並依使用者決策 B 將 runtime allowlist 封裝進 0.0.9-beta.3 Windows MSI／NSIS。 安裝或啟動 Yuzora 不自動註冊 Plugin；使用者由 bundled helper 明確 link exact resource path。Yuzora runtime 不新增 bridge service；只保留既有 session.snapshot、events.subscribe 與 typed consumer seam，不新增 metadata／session DTO。
版本條件：Plugin 以官方 Herdr v0.8.2 Stable／protocol 20 為最低版本；managed binary、Windows Stable ZIP、完整 ConPTY runtime 與封裝驗證必須同步更新。舊 protocol 19 server 不得半連線。

此文件是實作與發布計畫。Windows 11／WSL2 實機結果在使用者簽核前一律標示未驗證。Oracle／Scout 修正與使用者決策 D1=A、D2=Pi-only、D3=B（Windows installer bundled Experimental）已鎖定於下節；實作追蹤見 GitHub Issue #90。

02 · Scope & non-goals

已定責任邊界

主題決定理由
Host Runtime僅 Windows-native HerdrWSL 是 pane workload；不得啟動第二個 WSL Herdr runtime。
可支援 pane僅 Plugin entrypoint 建立Plugin 可控制自身 pane 的 argv／env；無法攔截既有或手動 wsl.exe。
Agent authorityWSL agent adapter 主動自報Windows process tree 看不到 WSL Linux Agent；terminal/screen 推論被禁止。
TransportWSLInterop 執行 Windows herdr.exe沿用官方 CLI，讓 Windows process 連 named pipe；不引入 npiperelay／localhost bridge。
Source IDyuzora:wsl:pi不冒充官方 herdr:pi。Claude／Codex custom source 延後。
Yuzora consumersnapshot/events only不讀 Plugin files、不解析 terminal、不推斷 distro 或 Agent；不新增 metadata／session DTO。
Native sessionadapter-log onlyCustom source 無法形成 Herdr persisted agent_session；report-agent-session 不在 MVP 驗收。Pi session id 可寫 log，不可投影、不可 resume。
Execution originMVP 不新增／不恢復若 Herdr wire 未提供權威欄位，Yuzora 不自行製造 execution_origin。
Unknown Attention保留現行行為不因 WSL adapter 靜音或降級 global unknown Attention。
New Agent dialog仍只啟動 Herdr manifest kindPlugin 不能註冊新的 agent start --kind；不得把 WSL entrypoint 偽裝進 catalog。
Windows deliveryBundled Experimental，明確 linkMSI／NSIS 以 individual resource mappings 內附 exact 10-file runtime allowlist；不封裝其他 adapters／scripts、tests 或開發 lib，不在 app startup 自動註冊或修改 WSL home。
Security boundary同 Windows 使用者信任模型Herdr v0.8.2 report API 無 pane-scoped token；MVP 不宣稱對抗同使用者惡意 spoof。
明確不在第一版範圍
  • 任意既有 pane 內手動執行 wsl.exe 的透明偵測。
  • 掃描 WSL /proc、Windows process tree 或 terminal output。
  • WSL Herdr provider、runtime target、socket relay、distro discovery UI。
  • OSC 21337 lifecycle authority、Herdr core fork、custom resume command。
  • 為 Plugin 建立 Yuzora 專用 Settings／對話框；先以 Herdr Plugin actions／CLI 操作。
  • Claude／Codex installer、action、adapter、test 與 Windows 驗收（延後 follow-up）。
  • Yuzora 可見的 native session／thread identity、report-agent-session、resume command 或 metadata token 投影。
  • 把 Claude／Codex 無法證明的狀態硬標成 working／blocked。
本計畫採用的假設
  • 初版 plugin 與 Yuzora 同 repo 共置，Windows installer 以 Tauri resource map 封裝 runtime allowlist；日後拆成獨立 repo 不改 runtime contract。
  • Installer activation 維持 explicit opt-in；bundled helper 只管理 exact bundled root，遇同 id 的其他 registration fail closed。
  • 目標 Windows 為 Windows 11＋WSL2，啟用 WSLInterop，且可從 WSL 執行 .exe。
  • Plugin runtime 使用 Windows PowerShell 5.1 相容語法，不要求使用者另裝 Bun／Node／Rust。
  • Agent adapter 使用專屬檔名與 marker，不覆寫 Herdr 官方 Windows-home integration。
  • Windows plugin 仍是 Herdr 官方 Preview 等級，因此 Yuzora 對外也標為 Experimental，直到使用者驗收通過。
  • 開發期以 herdr plugin link 為準；PowerShell 啟動需 -NoProfile -ExecutionPolicy Bypass，企業 GPO 鎖定環境列入 known limitation。
03 · Target architecture

單向投影，不建立第二條狀態真相

控制面

  1. Herdr plugin action 讀取 plugin config 與 focused context。
  2. Action 經 HERDR_BIN_PATH plugin pane open 開啟 plugin-owned pane。
  3. PowerShell wrapper 選定 distro／Linux cwd，fail-closed 清理 WSLENV 後 exec wsl.exe。
  4. Adapter manager 只 orchestrate；Pi hook 的實際檔案操作由 wsl.exe -d <distro> -- sh 在 distro 內執行。

資料面

  1. WSL Agent hook 取得 launch-time pane identity。
  2. 共用 reporter 經 translated HERDR_BIN_PATH 啟動 Windows herdr.exe。
  3. CLI 連到 owning named session，MVP 只呼叫 report-agent 與 release-agent。
  4. Yuzora 只從 snapshot／events 收到 agent projection。
關鍵 routing：先不分大小寫刪除既有 WSLENV 中所有 HERDR_SOCKET_PATH entries／flags，再把 Windows socket marker 改名傳入 YUZORA_HERDR_SOCKET_PATH/u。 reporter 僅在啟動 Windows herdr.exe 的該次 child env 暫時還原 HERDR_SOCKET_PATH，並以 HERDR_SOCKET_PATH/w 回傳 Windows process。

04 · Runtime contracts

環境、source、seq 與 lifecycle 契約

Win32 → WSL 環境傳遞

變數WSLENV entry用途限制
HERDR_ENVHERDR_ENV/u啟用 adapter gate必須等於 1。
HERDR_PANE_IDHERDR_PANE_ID/ulaunch-time pane alias跨 workspace move 後仍使用 launch id。
HERDR_TAB_IDHERDR_TAB_ID/u診斷／metadata不作為 report target。
HERDR_WORKSPACE_IDHERDR_WORKSPACE_ID/u診斷／顯示不自行改寫 Yuzora ownership。
HERDR_BIN_PATHHERDR_BIN_PATH/up轉成 /mnt/c/.../herdr.exe僅 Win32→WSL，避免回傳路徑再翻譯。
YUZORA_HERDR_SOCKET_PATHYUZORA_HERDR_SOCKET_PATH/u保存 owning named-session marker不可讓 stock Linux hook 誤認成 Unix socket。
YUZORA_WSL_DISTROYUZORA_WSL_DISTRO/u顯示與診斷不由 Yuzora consumer 推斷。
禁止與 fail-closed 規則：Herdr plugin pane 會強制注入 raw HERDR_SOCKET_PATH。Launcher 必須不分大小寫刪除既有 WSLENV 中每一個 HERDR_SOCKET_PATH entry（無 flag 或任何 flags），再只加入 Win32→WSL 的 YUZORA_HERDR_SOCKET_PATH/u。原始 named-pipe marker 不得進入 WSL stock hook；只在啟動 Windows herdr.exe 的 child env 暫時設 HERDR_SOCKET_PATH 並附加 HERDR_SOCKET_PATH/w。

Reporter child invocation

# 概念契約；實作由共用 reporter 封裝，不讓各 adapter 重複拼接。
HERDR_SOCKET_PATH="$YUZORA_HERDR_SOCKET_PATH" \
WSLENV="$(merge_wslenv "$WSLENV" 'HERDR_SOCKET_PATH/w')" \
"$HERDR_BIN_PATH" pane report-agent "$HERDR_PANE_ID" \
  --source yuzora:wsl:pi \
  --agent pi \
  --state working \
  --seq "$SEQ"

Sequence 契約

  • seq 對每個 (named-session marker, pane launch id, source) 單調遞增。
  • 共用 reporter 以 max(epochMillis, persisted + 1) 產生下一值，以 flock 原子寫入 $XDG_RUNTIME_DIR 或 ~/.cache/yuzora-herdr-wsl/。
  • 同一 hook process 內再加 local counter，避免同毫秒 collision。
  • 不把 API 回傳 ok 視為 seq 已被接受；trace log 保留 source／pane／candidate seq，Windows 驗收比對 snapshot。stale rejection 最多重試一次較高 seq。

Agent 能力分級

Agent本輪範圍State policyNative sessionExit
PiMVP：live identity + state依 Pi lifecycle event 映射 working／idle／blocked；source 固定 yuzora:wsl:pi。不呼叫 report-agent-session。若 hook 提供 Pi session id，只寫 adapter log。Yuzora 不投影、不持久化、不 resume。Report API 沒有 resume command 欄位。hook release-agent；pane 結束由 Herdr 自清。pane.exited cleanup 為 optional，只清 plugin seq／state 檔。
Claude延後 follow-up本輪不實作 installer／adapter／action／驗收。不承諾。不在本輪。
Codex延後 follow-up本輪不實作 TOML／hooks.json merge 或 adapter。不承諾。不在本輪。

Custom source 可驅動 report-agent，但 v0.8.2 session_ref_from_report 只接受官方 herdr:* allowlist；yuzora:wsl:pi 無法形成 persisted agent_session。文件與 UI 不得宣稱官方 integration 等價，也不得把 API ok 當成 session 已持久化。

06 · Implementation phases

九階段實作與驗收順序

P0

凍結基線與釐清 dirty tree

實作者

  • 記錄 branch、base SHA、selected Herdr binary 與目前 14 個 unstaged 路徑。
  • 逐一檢查相關 dirty diff，確認 optional execution_origin 與被刪研究／設計文件的最終意圖。

完成條件：所有相關 dirty 檔案都有明確 ownership；未獲確認前不進入修改。

P1

升級 Yuzora-managed Herdr 至 v0.8.2 Stable

實作者

  • 更新 macOS arm64／x86_64 與 Windows x86_64 至同一官方 v0.8.2 release；移除 Windows preview URL。
  • 以 GitHub release digest 與解壓後 exact file inventory 固定資產；Windows 保留完整 ConPTY runtime。
  • 更新 HERDR_RESOURCE_VERSION 為 baseVersion: "0.8.2"、protocol: 20。
  • 驗證 terminal observe／control 仍由 selected binary 提供，沒有 protocol 19 hardcode；必要時才調整 transport。
  • 記錄並回歸 0.8.2 行為變化：agent.prompt 在 blocked 時回 agent_blocked；agent start 等待 shell／interactive ready；pane.current 解析 calling pane；headless fallback 80×24 → 120×40。
  • 更新 operations 說明：19↔20 不相容、升級後須重啟舊 named-session server、Stable／Preview 分流。
  • 只更新 pin expectations；保留用來測舊 schema／compatibility 的 0.8.0 fixtures。

完成條件：managed asset tests、Rust Herdr tests、typecheck 全部通過；本機可證明 bundled binary --version=0.8.2、schema protocol 20。

P2

建立 Windows-only Plugin package

實作者

  • 新增 herdr-plugins/yuzora-wsl-agents/ 與 v1 manifest，最低 Herdr 0.8.2。
  • 定義 versioned config schema：default distro、distros、enabled agents（MVP 僅 pi）、optional Linux cwd policy。
  • 所有 runtime script 相容 Windows PowerShell 5.1；manifest argv 含 -NoProfile -ExecutionPolicy Bypass。企業 GPO 鎖定 ExecutionPolicy 列入 known limitation。
  • Startup 只檢查狀態並寫 plugin log，不自動修改 WSL home。
  • Actions 與 panes 均以固定 argv 組裝；使用者輸入永不拼進 shell string。

完成條件：Herdr v0.8.2 可 link/install manifest；Windows-only filter 與 min-version gate 正確。

P3

Plugin-managed WSL pane launcher

實作者

  • 從 HERDR_PLUGIN_CONTEXT_JSON 取 focused workspace/cwd，但不把 context pane id 當新 pane identity。
  • 以 config 選 distro；UNC workspace 必須匹配 distro，Windows path 透過 target distro 的 wslpath 轉換。
  • Fail-closed 清理 WSLENV：不分大小寫刪除所有 HERDR_SOCKET_PATH entries／flags，保留其他 entries 並去重，再追加 Win32→WSL contract 與 YUZORA_HERDR_SOCKET_PATH/u。
  • 把 Windows socket marker 複製到 alias YUZORA_HERDR_SOCKET_PATH；不把 raw HERDR_SOCKET_PATH 傳入 WSL。僅 reporter child 暫時設 HERDR_SOCKET_PATH/w。
  • MVP 只提供 WSL shell 與 Pi 固定 entrypoint；不接受任意 user string，也不開放 Claude／Codex entrypoint。
  • 失敗時顯示明確 distro／cwd／binary／interop 錯誤，不 fallback 到另一 distro。

完成條件：fixture tests 證明 WSLENV merge、Unicode／space path、UNC mismatch 與 missing distro 均 fail closed。

P4

Per-distro adapter install／status／uninstall

實作者

  • 以 wsl.exe --list --quiet 取得 inventory；處理 UTF-16LE／NUL，重用與 Yuzora backend 同等解析 fixture。
  • Windows 只 orchestrate：以 wsl.exe -d <distro> -- sh 在 distro 內執行 POSIX installer。禁止 PowerShell 透過 \\wsl.localhost 直接改 Linux home／chmod。
  • MVP 只安裝 Pi 專屬 extension 檔名與 version marker；不編輯 Claude settings.json 或 Codex config.toml／hooks.json。
  • 每個 adapter 寫入 version marker／checksum；status 分辨 absent、current、outdated、drifted。
  • Uninstall 只刪 plugin-owned files／marker；重複執行為 no-op；plugin uninstall 前文件要求先跑 adapter uninstall。
  • 多 distro 逐一回報，不因單一 distro offline 就覆蓋其他結果。

完成條件：temp-home fixture 能 round-trip install → status current → uninstall → no residue，且不破壞既有 hook。

P5

共用 reporter 與 Pi lifecycle adapter

實作者

  • 新增共用 reporter，集中 env validation、named-session routing、seq、retry、logging 與 CLI argv。
  • 從 Herdr v0.8.2 官方 Pi integration 的 event mapping 衍生，保留 license／來源註記，但 transport 改為 CLI reporter。
  • 回報 yuzora:wsl:pi、agent pi、working／idle／blocked。不呼叫 report-agent-session；不新增 Yuzora metadata／session DTO。
  • 若 Pi hook 提供 native session id，只寫 adapter log，明確標 non-resumable。不得把它當成 Yuzora 或 Herdr persisted session。
  • 報告失敗不可阻止 Pi；採有限 retry／queue，不輪詢、不在每個 token/output 事件 spawn herdr.exe。seq 用 flock；stale rejection 最多重試一次。
  • 正常 exit 呼叫 release-agent；crash 時由 pane lifecycle 收斂，不建立 daemon。

完成條件：adapter unit harness 能重播事件序列，證明 state transitions、seq 與 release argv 精確；測試不得要求 Yuzora 顯示 session id。

P9

發布、支援矩陣與回滾

實作者 + 使用者核准

  • Plugin 以 0.x Experimental 隨 Windows Beta installer 封裝；列出最低 Herdr、Windows、WSL 與 agent 版本。
  • Installer inventory 必須與 exact 10-file allowlist 完全相等並逐檔比對 source SHA-256；任何額外 adapter／script／test／lib 都 fail closed。
  • Windows candidate／Release job 以 Windows PowerShell 5.1 執行 UTF-8／UTF-16LE byte fixtures、解析 packaged scripts，並從 MSI／NSIS extracted resource path 做 status／link／foreign-root refusal／unlink。
  • README 區分 Stable Herdr runtime 與 Preview plugin surface，不把 preview 能力標成 stable。
  • Bundled helper 對 exact root 提供 status／link／unlink；不自動註冊，不覆寫同 id 的其他 source。
  • 提供 reinstall 更新流程；Herdr v1 無 plugin update，不暗示自動更新。
  • 回滾順序：關閉 plugin panes → uninstall WSL adapters → disable/uninstall plugin → 保留 Yuzora snapshot/event consumer。
  • 只有 P8 證據完成後，才更新 QA／changelog／release notes。
  • Beta merge 前設定 accepted candidate tree SHA 與本 repository evidence URL；Release Guard 在 tag 前精確比對 successful-main tree，未 attested 或 tree drift 一律停止。

完成條件：安裝與回滾文件可由另一位工程師照做，且不需知道內部 bridge 實作。

Fixture 覆蓋

  • WSL distro list：shipped PowerShell 直接讀 StandardOutput.BaseStream raw bytes；Windows PowerShell 5.1 fixture 覆蓋 UTF-8、UTF-8 BOM、UTF-16LE BOM／NUL、空輸出。
  • CWD：Windows drive、verbatim prefix、\\wsl.localhost、\\wsl$、space、CJK、distro mismatch。
  • WSLENV：case-insensitive deny-list 刪除所有 HERDR_SOCKET_PATH entries／flags，再去重並追加 alias／child-only /w。
  • Config：schema version、unknown keys、invalid distro、path traversal。
  • Install：in-distro POSIX Pi installer round-trip、既有 hooks 不被覆寫、重複 install、drift、uninstall。
  • Reporter：missing env、custom source、named session marker、seq restart、flock、stale retry、timeout、release。不含 report-agent-session。
  • Agent events：Pi complete live state lifecycle；不得把 session id 當 Yuzora fixture 欄位。
  • Yuzora：custom source 不需新增 wire type；unknown state 維持現行 Attention 行為。
  • Packaging：Windows resource map 為 exact allowlist，source path 全部存在，且不含 tests/／lib/。
  • Bundled helper：status JSON、same-root idempotent link、foreign-root link／unlink refusal、exact-root unlink。
不以 macOS 假裝 Windows 驗收：PowerShell／ConPTY／named pipe／WSLInterop 的真實相容性只能由 P8 實機證據判定。自動化 fixture 只驗證 deterministic logic 與 command construction。

09 · Risks

主要風險與 fail-safe

風險影響緩解停止條件
Herdr Windows Plugin 仍屬 previewaction/pane 行為可能 regressmin version gate、0.x Experimental、實機 matrix、保留 CLI fallback。Plugin pane 無法穩定啟動或 context/env 不一致。
Protocol 19→20 不相容舊 server／新 client 無法連線binary/connector 同步、明確 restart runbook、不自動殺 server。任何半連線、silent fallback 或跨版本混用。
Named-session routing 錯誤report 進入 default 或其他 sessionsocket marker alias＋child-only HERDR_SOCKET_PATH/w；雙 session manual test。W06 任一次 routing 錯誤。
seq stale／replay新狀態被舊高 seq 壓住persistent monotonic seq；logs；不信任 API ok 等於 accepted。重啟 adapter 後 state 無法更新。
同使用者 spoof任意本地 process 可對其他 pane 自報誠實揭露 same-user trust；custom source；不宣稱 security isolation；提 upstream token/ACL。產品需求升級為 hostile-local-user model。
Custom source 無 persisted session誤把 API ok 當 resume／Yuzora sessionMVP 不呼叫 report-agent-session；session id 僅 log；文件明確 non-resumable。任何 Yuzora DTO／UI 出現 native session 或 resume 宣稱。
Config merge 破壞 user filesAgent 無法啟動或其他 hooks 消失Windows 只 orchestrate；in-distro POSIX installer；Pi-only marker files；idempotent uninstall。installer 透過 UNC 直接改 Linux home，或改寫 Claude／Codex 檔。
WSL UNC／Unicode path錯 cwd 或 command injectionargv-only、固定 shell fragment、distro match、fixture＋實機。必須拼接未轉義 user shell string。
Plugin uninstall 無 hookWSL adapter 殘留明確先 uninstall adapters；殘留 adapter 在缺少 Herdr env 時 no-op。殘留 hook 會阻止 Agent 或造成錯誤。
10 · Release & rollback

先 Experimental，Windows 證據後再擴大承諾

ALPHA

Pi-only PoC

Plugin-managed pane、default distro、Pi lifecycle；只供開發者 link 測試。

DEFERRED

Claude／Codex follow-up

不在本輪。後續才評估 conservative adapters；仍不得宣稱 resume 或官方 source 等價。

SUPPORTED

Evidence-gated

只有使用者完成 P8 且對指定版本矩陣簽核後，才可在 Yuzora release notes 宣稱支援。

回滾順序

  1. 結束 Plugin 建立的 WSL Agent panes。
  2. 執行 Plugin action／script 對所有 configured distros 卸載 adapters。
  3. 檢查 status 為 absent，確認 user-owned hooks 未被移除。
  4. Disable／uninstall Herdr plugin；config/state 可保留供故障分析。
  5. Yuzora 保持 Windows-native Herdr snapshot/event consumer；不恢復舊 bridge。
  6. 若回滾 Herdr 0.8.2，必須把所有 client/server 同步回 protocol 19 並重啟；不得只回滾單一平台。
發布命名：Herdr Runtime 可稱 v0.8.2 Stable；本 Plugin 在官方 Windows plugin surface 尚為 preview 時，只能稱 Experimental Plugin，兩者不得混寫。
