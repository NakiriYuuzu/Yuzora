待確認的基準決策

生效基準（使用者修正後）：涵蓋 App DOM Dialog Modal，包括小型確認框與表單；Alert / AlertDialog（含 AppDialogHost）不參與 80% 與可調整大小。仍排除 Popover、Menu、Drawer、原生 OS 對話框、瀏覽器 prompt/confirm 與 Preview iframe 對話框。
  1. 沒有儲存過尺寸時，in-scope Dialog Modal 實際寬高均為目前 WebView viewport 的 80%。
  2. 尺寸以穩定的 Modal ID 分別保存，重新開啟仍保留；不是所有 in-scope Modal 共用一個尺寸。
  3. 保存 viewport 比例，不保存固定 pixel；App 視窗改變時 Modal 會維持相同比例。
  4. App 視窗縮小時只暫時 clamp，不能覆寫使用者偏好；視窗放大後恢復原偏好。
  5. 右邊界控制寬度、下邊界控制高度、右下角控制兩者；邊界支援 pointer capture 與鍵盤方向鍵。
  6. Home 或雙擊 resize handle，將該 in-scope Modal 重設為 80% × 80%。
  7. 最大尺寸保留每側 16px 安全距離；最小尺寸由共用預設與個別 Modal 覆寫共同決定。
  8. Alert / AlertDialog（含 AppDialogHost）維持 compact content-sized，不套用 80%、resize handles 或 size persistence。
UX 代價：in-scope Dialog 的確認框、密碼框、文字輸入框也會變成 80% 視窗，內容周圍會有大量留白。Alert / AlertDialog 則維持 compact，不套用此代價。historical superseded 早期「所有 Modal」字面需求已被使用者修正覆蓋。

目的與成功條件

建立單一、可測試、可持久化的 Dialog Modal 尺寸契約（排除 Alert / AlertDialog），取代目前散落在 in-scope Dialog callsite 的 400px、620px、720px、1040px、80vh、88vh 等硬編碼。

  • 首次開啟任一 in-scope Dialog Modal：寬度 = viewport 80%，高度 = viewport 80%。
  • 使用者可調整寬、高或兩者，過程不破壞 Radix focus trap、Escape、outside click 與 nested dialog。
  • 每個 Modal 的自訂尺寸獨立保存，重啟 App 後仍可恢復。
  • 所有內容列表與閱讀區使用既有 shadcn ScrollArea；CodeMirror、xterm 等既有例外不更動。
  • Alert / AlertDialog（含 AppDialogHost）維持 compact content-sized，不套用 80% 與 resize handles。
  • Popup、Popover、Context Menu、Terminal Drawer、Tauri native dialog 的尺寸不受影響。
  • 不新增第三方 resize 套件；現有 shadcn Resizable 是 panel-group 元件，不適合外層 Modal 邊界。

風險與控制

  • 80% 小型 Dialog 確認框過大：in-scope Dialog 產品決策；Alert / AlertDialog 則維持 compact content-size。
  • Radix focus/dismiss 退化：resize handle 置於 Content 內，所有 pointer event 必須阻止被判定為 outside interaction。
  • jsdom 不計算真實 vw/vh：單元測試驗證 math 與 inline style；真實 Tauri 視覺驗收需另獲 E2E 同意。
  • 內容 overflow：逐 host 使用 ScrollArea，禁止在共用 DialogContent 上直接加 bare overflow-auto。
  • 儲存損毀：schema validator 遇到 NaN、Infinity、負值、未知 version 時回到 0.8，不讓 Dialog 無法顯示。
  • Preview native child webview z-order：overlayStore 目前未涵蓋所有 local modal；這是 scout 發現的既存缺口。除非驗證證明本需求因此不可用，先記錄為獨立 follow-up，避免擴張 scope。
  • dirty worktree：實作前記錄 baseline；不可還原使用者既存變更。

請確認

Q1 — 小型確認框與表單是否也必須強制 80%？

現行答案（使用者修正後）：in-scope Dialog 是；Alert / AlertDialog 否。 Dialog 確認框/表單維持 80% 可調整；Alert / AlertDialog（含 AppDialogHost）維持 compact content-sized。若再縮 Dialog scope 只涵蓋內容型 Modal，則會變成 Settings、Command Palette、Symbol Picker、External Resolver、Git Diff、Herdr Inspector 等集合。

Q2 — 自訂尺寸是否需要跨 reopen / App restart 保存？

本計畫預設：每個 Modal 分別永久保存。若只需本次開啟有效，可移除 storage phase，實作量與風險會顯著下降。

Q3 — 是否接受「右邊＋下邊＋右下角」並支援鍵盤的 resize UI？

本計畫預設：接受。不採 native CSS resize: both，因為其鍵盤可及性、持久化 callback 與 WebView 一致性不足。

Q4 — dormant Herdr Agent Inspector 是否納入？

本計畫預設：納入 source contract。即使目前沒有 production mount，也會在掛載時符合相同規則。

Q5 — 80% 是 WebView 內容區，還是包含 native window decoration？

本計畫預設：WebView CSS viewport（window.innerWidth/innerHeight）。這是 DOM Modal 可可靠量測且跨平台一致的「App 可視內容區」。

不在本計畫內

  • 不調整 Tauri 主視窗本身大小。
  • 不新增拖動 Modal 位置；Modal 仍維持置中。
  • 不改 Alert / AlertDialog、Popover、Sheet、Drawer、Menu、Terminal drawer 的 compact / non-resizable 行為。
  • 不替換 Radix Dialog，也不安裝新的 resize library。
  • 不順手修正 overlayStore、release、Herdr 或其他 scout findings，除非它們直接阻擋本功能。
  • 不在未取得本次對話明確同意前執行 browser/E2E 工具。
  • 不執行 git add、git commit、git push。
