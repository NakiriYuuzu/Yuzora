本次修正

  • 建立 herdrScrollStrategy：0.8.2／protocol 20（pane.get 無 pane.scroll）使用 connector terminal.scroll；0.9.0／protocol 22 同時具備 pane.get／pane.scroll 時才使用 pane API；能力未知時不呼叫捲動 API。
  • pane scroll metadata 暫時回傳 null 或讀取失敗時，退回 terminal.scroll，避免 transient failure 變成輸入中斷。
  • 保留既有單一 in-flight scroll drain 與 coalescing，避免快速滾輪佔滿 terminal input queue。

效能與穩定性

  • 基線與回歸：frontend 全套 219 test files／2676 tests PASS；frontend production build 約 7.11 秒；host/app cargo check --locked --all-targets PASS；release contract 45 tests PASS。
  • 原生 macOS 穩態觀察：狀態列約 6% CPU、165MB App＋managed processes，3 個 managed tools 約 28MB；三個 terminal 仍保持可操作。
  • HERDR scroll 路徑的可量化改善是 IPC 背壓：快速 wheel 維持單一 in-flight request，測試確認兩次併發輸入只產生兩個有序 remote scroll；pane API 暫時不可用時不再拋出可見錯誤。
  • 跨平台 packaged before/after p50/p95 尚未可量測，因候選包被 host resource contract 阻擋；不以開發版主觀速度推論 packaged 結果。

剩餘阻擋與後續回歸

必須在四個 Unix runner 重新執行 bun run host:prepare，產生與 0.0.14 相符且 hash 正確的 host helpers／HERDR manifests，才能解除 packaged candidate、安裝／升級與 updater session-continuity BLOCKED。Windows native HERDR session 也必須在 Windows App 提供後補做同一矩陣。

固定回歸案例已落在 herdrCapabilities.test.ts、herdrTerminalTransport.test.ts、既有 host capability／scroll tests 與 release contract tests，會隨 CI 執行。
