HERDR 只在 connector terminal.scroll 依子程式模式分派（上游 src/server/pane_input.rs apply_scroll → src/pane/terminal.rs wheel_routing()，0.9.1 與 0.9.3 相同）；JSON connector 在 0.9.3 仍丟棄 MouseCapture，client 無從得知子程式模式。v0.0.16（使用者安裝版）全部情境失效；09-28 未提交修法修好 A、C，但 B 仍失效。

修正（使用者選方案 A）

  • src/terminal/terminalTransport.ts：supportsHerdrApplicationWheel 允許時，實體滾輪一律送 terminal.scroll＋游標格；pane.scroll 只保留給 scrollbar 拖曳，以及指令不可用或斷路器跳開時的 fallback。不再先讀 pane 範圍（少一次 round trip）。
  • remote stream 佇列滿（stream-closed-or-busy）視為背壓：丟棄排隊中的滾輪，不讓斷路器永久跳開；失敗時一併清除殘留的 pending 滾輪狀態。

代價：一般 shell 的歷史捲動改走相對指令，與 F3 選的 pane 路徑手感不同。WSL protocol 22 也會每次滾輪都送 terminal.scroll（歷史上 WSL bridge 曾因此斷 connector），需 Windows 實機驗收。

2. 遠端 host-…-limit 後 terminal 失效

使用者環境：SSH runtime host「Oracle-SG」（高延遲），同時開 10 多個 agent session。host-*-limit 類錯誤只出現在遠端 helper 路徑，本機 macOS 路徑沒有對應上限。

根因（程式路徑確認）

  • src-tauri/src/host_streams.rs host_stream_open：stream_openings.try_acquire()（8）失敗即回 host-stream-open-limit；permit 持有到 Open 回覆（SSH events 另含多次 round trip 的 capabilities 查詢）。tab／Space 一次顯示多個 pane、重連、啟動還原都會造成 burst。
  • HerdrTerminalPage：初次開啟失敗只印 [Failed to open Herdr terminal…]；recoverOutput 失敗只顯示狀態；Reconnect 按鈕只在 takeover 時出現 → 該 leaf 永久失效，其他 terminal 正常。
  • 遠端 stream 中斷以 {type:"error", code:"host-stream-closed"} 送達，transport 留著已死的 session id。

修正

  • Rust：新增 HostConnection::acquire_stream_opening（30 秒上限、host 斷線即取消的 FIFO 排隊），逾時回 host-stream-open-wait-timeout。
  • 前端：isRetryableHerdrConnectError；自動路徑（初次開啟、resync、輸入失敗、遠端 stream 中斷）以 0.5／1／2／4／8 秒退避重試。connector 穩定 10 秒才恢復重試額度，所以「一開就死」（有沒有 full frame 都一樣）最後會停在 Reconnect，不會無限重開。手動 Reconnect（含 takeover）一次一試，不用 timer 搶回控制。
  • transport 把 host-stream-closed 視為 connector 遺失，不當成 pane exit，因此不會讓 BSP leaf 收合。
  • i18n：herdrTerminal.reconnecting（en／zh-TW）。

尚存限制：每 host 32 條 stream 上限（too-many-host-streams）在 10 多個 session 且 pane 很多時仍可能觸頂，重試只能延後 Reconnect 出現。每條遠端 stream 各佔一條 SSH session channel，若主機 sshd 的 MaxSessions 是預設 10，會成為另一個確定性的硬上限，請在主機上以 sshd -T | grep -i maxsessions 確認（未驗證）。
