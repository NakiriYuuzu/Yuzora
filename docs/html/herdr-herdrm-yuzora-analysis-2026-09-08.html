Herdr、herdrm 與 Yuzora
執行核心、桌面操作與完整工作區

三者的責任層次不同：Herdr 擁有程序與 terminal runtime；herdrm 提供精簡的原生操作介面；Yuzora 把 Agent、Files、Git、LSP 等能力整合到同一工作區主機。Yuzora 的下一步應先驗證斷線與壅塞時的生命週期，再評估上游新協定。

本輪是原始碼架構分析，未執行 build、測試或實際 SSH／GUI 斷線驗收。風險推論不等於已重現缺陷。只新增本報告，未修改產品程式碼或執行 Git 寫入。

Yuzora 的權威決策為 Domain Context 與 ADR-0003：每個工作區只有一個執行 authority，Windows 使用 WSL2，Linux／macOS 使用原生 runtime，SSH 支援 Linux／macOS；目前整合基準是官方 0.8.2／protocol 20。

1. Herdr：server 持有程序，client 投影狀態

  1. daemon 與 UI 分離。Headless server 維護 AppState、PTY 與事件迴圈，client attach／detach 不代表程序生命週期結束。這支持 Yuzora 退出時僅清理自己持有的 connector。headless.rs
  2. master 區分公開 JSON API 與 private binary client protocol。herdr.sock 提供 JSON API；herdr-client.sock 承載同版 client 通訊。Endpoint 契約另有 generation、codec 與 capability negotiation。Yuzora 不宜把 private wire format 視為穩定整合 API。endpoint.rs
  3. 狀態與畫面分流。ClientShellSnapshot 攜帶 boot ID、revision 與 workspace／tab／pane／agent projection，surface frame 另行傳輸；control 與 render lane 也分開。可借鑑的是慢畫面消費者不拖住控制操作的設計。snapshot · client transport
  4. domain identity 不依賴排序。AppState 保持純資料，workspace public ID 與 display order 分離，tab 組合 pane map 與 layout tree。Agent、plugin、integration 也有獨立 API namespace。AppState · workspace
  5. terminal 核心是 parser／PTY／actor。採 Ghostty/libghostty-vt、portable-pty 與 PTY actor；TerminalRuntime 仍包裝 legacy PaneRuntime，不能認為模組拆分已完全完成。runtime wrapper · PTY actor
  6. master remote 使用 SSH endpoint 與 supervisor。遠端 attach 檢查 endpoint generation、surface interest、health check 等能力；live handoff 與 session persistence 是不同機制。最新 HEAD 特別要求遠端 server replacement 的明確同意。這是未來升級評估材料，不是本輪建議替換 Yuzora 現有 provider。remote attach · supervisor

分析限制：上游 Windows 支援未完成逐平台核對；Cloud transport 也未確認為完整可用實作。

2. herdrm：值得借鑑的原生操作介面與診斷

  1. SwiftUI console 分層清楚。HerdrM 負責 UI，HerdrKit 承載 domain／RPC／device，HerdrSSH 負責原生 SSH，main 新增 HerdrMobile。產品聚焦 Spaces、Agents、Terminals 與 PTY attach。project.yml
  2. 每裝置一個 service。macOS HerdrService actor 管理 local socket 或 SSHTunnel。RPC 使用 NDJSON，每次一般 request 新建連線並設 15 秒 response timeout；event subscription 使用長連線。相容檢查要求 protocol 至少為 17。HerdrService · SocketRPC
  3. macOS 遠端沿用 OpenSSH。ssh -N -L local.sock:remote.sock 使用 config、agent 等現成能力，並設 forwarding／keepalive 選項。錯誤分類涵蓋 socket 不存在、refused、stale socket 與 streamlocal forwarding 被禁止，適合借鑑為可行動的診斷。SSHTunnel · errors
  4. macOS 採 snapshot + event invalidation。每裝置依序 connect、snapshot、manifests、event stream；事件觸發 200ms debounce refresh，失敗以 1 至 30 秒 backoff 重試，認證失敗則停下等待使用者處理。AppModel
  5. terminal 的 UI identity 是實際工程重點。SwiftTerm 啟動官方 attach；PTY EOF 顯示 reconnect overlay，layout 使用 AnyLayout 保留 terminal identity，避免切換分支重建 attach process。這比單純複製 sidebar 外觀更值得參考。TerminalView
  6. iOS 是不同傳輸與互動模型。libssh2 direct-streamlocal 為 RPC、event、PTY 提供通道；事件斷線後保留 snapshot 並標示失敗，沒有 macOS 同等自動 backoff loop。一般 prompt 與 raw TUI 輸入分開處理。共用 SSH session 的 operation mutex 值得做延遲量測，不能單靠 source 推定已有性能問題。MobileTransport · SessionDriver

借鑑建議：錯誤分類、EOF 重連提示、terminal identity 保留。移植前需重新核對 pane-scoped event subscription、owner/generation 與 backpressure；本輪沒有證明 herdrm 具有 Yuzora 完整工作區所需的同等保護。

3. Yuzora current：整合邊界已建立，重點在失敗路徑

架構鏈為 React／Bridge／store → typed IPC／herdrProvider → Rust host service／helper → 來源主機上的官方 Herdr。Named Session 以 hostId + sessionName 識別，連線 owner 再帶 generation；Terminal Session 與 Agent Session 依領域定義分開。

原始碼支持的設計

  • 集中 routing 與 stale response 防護。runtimeIdentity.ts 定義 owner，herdrProvider.ts 統一路由，remote stream identity 納入 host 與 generation。
  • 主機握手與有界併發。host_service.rs 驗證 owner／generation／Hello；control request 與 HERDR call 有各自併發及等待限制。host_herdr.rs 使用 SSH direct-streamlocal。
  • 公開能力與 connector ownership。host/src/herdr_service.rs 集中 capability/schema gating，connector 綁定 named session；shutdown 只清理 Yuzora-owned connector，不停止 Herdr server／pane。
  • 快照与訂閱世代。HerdrBridge.tsx 管理 subscription generation、重試及 fallback；herdrStore.ts 拒絕過期 subscription 更新。
  • 輸入不重播。terminalTransport.ts 有 open generation、sequence、256 KiB 待傳限制及一筆 in-flight input；失敗時丟棄待傳尾端。

待驗證風險，依建議優先級排序

優先：remote terminal close 與一般 error 混在一起

已確認的局部路徑 herdrProvider.ts:103 附近將 host stream closed 轉成 error / host-stream-closed。terminalTransport.ts:290 附近只有 terminal closed 才清除 sessionId、discard input 與推進 generation。頁面的 error handler 只顯示狀態；resync 才會 release／reopen。

風險推論 若只有該 stream 斷線、host owner 仍有效，terminal 可能保留失效 attachment。主機整體斷線後是否有其他清理流程補足，需要實機與整合測試；本輪未宣稱已重現 zombie terminal。來源：provider、transport、頁面事件處理，約 921–946 行起。

其次：SSH event 消費端的 backpressure 證據不足

host_streams.rs:349 附近直接把 SSH event 送到 Tauri Channel；同函式的 bounded mpsc 是 command queue，不能當成 event consumer queue 有界的證據。應以 burst／慢 UI 驗證記憶體、延遲與取消行為。這不是「整個 SSH stack 完全沒有 backpressure」的斷言。來源：host_streams.rs、對照 helper streams.rs。

其次：connector stdin 寫入的阻塞界限

host/src/herdr_service.rs:2707 的 send_control 持有 stdin mutex 後同步 write_all／flush，這個函式內沒有寫入 deadline。外層 request timeout 是否足以終止底層阻塞仍需驗證；應用停止讀 stdin 的受控 connector 測試取消與清理。來源：herdr_service.rs。

契約整理：protocol 19 註解不等於已證實相容缺陷

herdr_transport.rs 註解仍提 0.8.0，herdrTypes.ts 多處提 protocol 19；這可能描述歷史或最低版本。另一方面，host_bootstrap.rs:151–165 對 managed artifact 明確要求 0.8.2／20。應驗證外部安裝與 managed artifact 的實際協商規則，再決定修改契約或文件；本輪不把註解差異評為 High 缺陷。
