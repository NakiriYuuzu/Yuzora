新發現與修正

在 d6e20c3 的 Windows GUI，從 WSL 頁籤選 Ubuntu-26.04、瀏覽 /home/yuuzu 並按開啟資料夾，對話框關閉後工作區仍停在原先 Windows 路徑。原因是 RuntimeFolderBrowser 把登記後工作區的 isCurrent 判斷綁在 browseGeneration；選擇器卸載會增加 generation，導致剛選出的工作區立即失效。

a01f9556032b552af9715cc709bce324574164e5 將工作區有效性綁到主機 connection owner，選擇對話框本身仍用 generation 丟棄過期回應。主機斷線時依然失效，未放寬 runtime／protocol gate。僅提交一行修正與 16 行回歸測試，其他未提交的資源回收／介面工作保留。

從已安裝 d6e20c3 建立乾淨來源副本：新增測試先得到 1 failed／18 passed（對話框關閉後 callback 錯誤回傳 false），套用一行修正後 19 passed；相關 folder／remote workspace／workspace actions 共 45 passed，typecheck、lint（0 errors）及 frontend build 通過。完整 CI attempt 2 的 11 個 jobs 均 success。Windows 第一次已通過 schema／snapshot／events／observer／controller／input／resize，但暫存目錄清理遇到 EBUSY；只重跑失敗 Windows job，於相同 SHA 通過，未修改或略過 gate。此清理偶發失敗未在本輪修正。

現在如何開啟 terminal

  1. Windows：在左側 Herdr 選單選「Windows 本機 · default」；WSL：先在設定啟用 WSL，再選 Ubuntu 主機與 default。
  2. 空 Session 可按「選擇資料夾並開啟 terminal」，或選單「新增 terminal」，選完資料夾即建立 Space 與第一個 terminal。
  3. 已有 Space 時，點選分支，再用「新增 terminal」增加分頁。要為另一個資料夾建立 terminal，使用「從資料夾建立 Space」。一般「開啟資料夾」只切換檔案工作區。

本輪驗證的是每個 Space 內的 terminal 分頁；沒有宣稱新增了獨立命名 HERDR server Session 的 GUI 管理功能。原始問題的「server 有執行」本身不足以證明使用者能找到建立入口，前輪已補上空 Session 按鈕與主機標籤。

RDP 傳送 Ctrl+S 在本次操作未生效；GUI「儲存」及寫回 WSL 均成功。尚未判定該快捷鍵是 RDP 轉送還是 app 處理問題，本輪不宣稱快捷鍵通過。此實機為 Windows 11／Yuuzu／Ubuntu-26.04，並非原始 herrytsai／Ubuntu-24.04；SSH 與其他 distro 沒有在本輪重跑完整 GUI 驗收。
