HERDR 背景更新不再替空工作區開啟資料夾

HERDR 已有專案，但 Yuzora 尚未開啟工作區時，背景 snapshot 原本仍會進入 focused tab 的恢復流程。修正後，背景恢復只作用於 Yuzora 已開啟、且 canonical path／主機身分相符的工作區；其他專案等待使用者主動選取。

原因與重現

原條件只在 workspacePath 存在時檢查身分，不存在時反而允許恢復。若開啟過程需要 Windows 資料夾綁定，取消被回報為尚未完成的恢復，下一次 snapshot 就會再次開啟選擇框。

回歸測試執行真實的 HerdrBridge、herdrStore、workspaceActions 與 folderPickerStore，僅 mock 平台與原生 I/O。修正前：模擬 Windows，在初次啟動及三次 snapshot 更新中開啟選擇框 4 次；模擬非 Windows，會擅自開啟 HERDR 的專案路徑。修正後兩種情境都不會開啟資料夾或新增 terminal 分頁。

變更

HerdrBridge.tsx 新增空工作區與缺少 Space root 的拒絕條件。既有已開啟資料夾的 terminal 恢復、同路徑不同主機的隔離、explicit Space／Agent activation 與取消競態重試皆保留。

新增跨元件與 store 的單元回歸測試，涵蓋取消後持續更新的實際 store 行為；既有 Bridge 測試 同步明確設定已開啟工作區，並加入尚未開啟工作區的情境。

驗證

6 個相關測試檔、75 tests 全數通過，涵蓋 Bridge、events、herdrStore、workspaceActions 與 FolderPickerHost。修改檔案 ESLint、typecheck、production build 與 git diff --check 通過。Build 僅保留既有 bundle／dynamic import 警告。

啟動工作區恢復與 polling policy 的 2 檔 27 tests 亦通過；本次合計 8 檔、102 tests 通過。

本次未操作 GUI 或執行瀏覽器自動化；開發伺服器 localhost:1420 已確認提供修正後的 guard。若畫面仍留著修正前開啟的彈窗，取消一次後可繼續測試。

未 staging、commit 或 push。未停止 HERDR 的既有專案與 terminal 程序。
