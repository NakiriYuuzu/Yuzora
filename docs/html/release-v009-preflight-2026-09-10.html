Pages 部署

首輪 PR CI 暴露乾淨 checkout 缺少 demo/ 的測試順序問題；已把 Pages 建置移到測試前。本機移開生成目錄可重現失敗，重新建置後 15 項官網測試全部通過。README 與 operations 同步列出準備步驟。

Linux PostgreSQL memory gate 原先限制總 RSS 64 MiB，首輪量得約 100 MiB；改為暖機後固定追蹤同一組 helper PIDs，限制查詢引起的增量小於 64 MiB。本機實際 PostgreSQL 的舊無界讀取負向驗證增加 263,995,392 bytes，仍會失敗；還原按需讀取後增加 294,912 bytes，完整 PostgreSQL matrix 通過。Linux 最終 baseline／peak／growth 與 CI 結果會記錄於 PR。

依使用者確認，沿用 GitHub Actions 部署 GitHub Pages，source 為 workflow，不建立 gh-pages 分支。Workflow 安裝 frozen dependencies、產生角色、建置 Demo，再上傳完整 site/。Demo 使用相對 assets，支援 /Yuzora/demo/。Pages 仍獨立於 main CI 觸發，部署成功不等於同來源通過 CI。
