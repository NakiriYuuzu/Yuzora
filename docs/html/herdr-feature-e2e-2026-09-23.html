真實管理 runtime：11 組檢查

完整管理 evidence.json 保留實際 request／response、通過清單、Session 隔離與 cleanup 結果。這些不是 fixture 預設回覆。

  1. 獨立 HOME／XDG，初始沒有執行中或已儲存的使用者 Session；預設的 stopped placeholder 位於測試 root。
  2. 建立／啟動 named Session、重複啟動回報未再次啟動；實際 HERDR 0.9.1、protocol 22、compatible socket 位於測試 root。
  3. Production capability gate 提供管理操作。
  4. 真實臨時 Git worktree 建立、關閉／重開、移除；dirty checkout 拒絕普通移除，明確 force 後移除。
  5. Pane 搬至新 Space、既有 tab、新 tab；跨 Space 依新 ID 操作，同 Space 保持 pane identity，snapshot 與回傳一致。
  6. Claude／Codex 配置安裝、故意變舊後偵測 outdated、更新回 current、解除安裝；原有自訂配置保留。
  7. 本機 mock pi process 的 start、中文 prompt、wait、rename、explain、send-keys 通過；Ctrl+C 確實終止 Agent 並釋放名稱，既有 Pane 保留。沒有呼叫 AI provider。
  8. 無效 wait timeout 與不存在的 Agent target 維持 error，沒有被當作成功。
  9. Session stop 保留 state，重新 start／load 還原工作區。
  10. Session stop／delete 後從儲存清單移除。
  11. Cleanup 確認只有腳本自己的測試 Session server 停止；證據與必要暫存 fixture 留存供診斷。

agent.start 的 public API 成功表示啟動已接受，可能仍有 launch_pending: true。timeout_ms 控制 server 的啟動期限；官方 CLI 另外等待 readiness。測試讀取 ready 狀態後才傳送 prompt；Yuzora 提示文字已反映此語意，沒有重做 host polling 或自動重送。

真實原生 client：10 項檢查

最終 result.json 與 完整 frame transcripts 為實際 native stream 證據。最終版本連續三次通過；攜帶的是最後一次完整記錄。

  1. 隔離的 HERDR 0.9.1／protocol 22 server。
  2. Production native client 開啟、ANSI frame 與鍵盤輸入。
  3. Resize 被採用，shell 保持可互動。
  4. 用鍵盤 Copy mode 搜尋螢幕外歷史，輸出與預期文字完全一致的 OSC 52；此項驗證協定內容，不宣稱 OS clipboard 已被實際讀寫驗收。
  5. 官方 client 轉送 inline Kitty graphics payload。
  6. Production feature 開啟 trusted local plugin popup；鍵盤有效，ordinary pane topology 不變。
  7. Production feature 開啟並繪製 trusted local plugin pane。
  8. 關閉 client 回收所屬 helper，server 與 pane identity 持續存在。
  9. Native client 關閉後，一般 pane connector 重新連接並接收輸入。
  10. 同一執行中 Session 可再開啟 native client。

Cleanup 停止且僅停止該測試 Session，刪除其暫存 runtime root。可讀畫面記錄：input、resize、Copy/search、Kitty、popup、plugin pane、reopen。

尚未完成與適用限制

  • Windows MSVC build：本機缺少 Windows SDK，之前 C dependency 缺 assert.h；需要適當 runner。

  • 真實 Windows SSH：PowerShell byte forwarding、named pipe、ConPTY、非 ASCII 路徑與斷線重連尚未在 Windows 主機上驗收。

  • 五平台 runtime payload：目前本機仍缺 Windows target 與完整新 manifest 集合，runtime:verify 尚不通過；不能將既有 artifacts 或先前 CI 結果當成本次 source 的打包結果。

  • 完整 Tauri webview：本輪 browser UI 與 host runtime 分別驗證，尚未完成包裝後的 Tauri 原生 webview 端到端 GUI 驗收。

  • OS 通知與 clipboard：只驗證通知 fixture 狀態與 OSC 52 協定；沒有驗證 OS notification／真實 Tauri toast 彈出或系統 clipboard 完整流程。

  • AI 與外部整合：Agent 使用 mock pi；Claude／Codex 測的是實際配置檔安裝與更新，沒有登入或呼叫供應商。其他 integration 只做 inventory；第三方 GitHub plugin 安裝與網路建置沒有在此本機測試中執行，popup／pane 使用 trusted local fixture。
