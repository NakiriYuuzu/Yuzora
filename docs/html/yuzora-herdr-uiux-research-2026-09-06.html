① 當前 Yuzora 專案

Yuzora 是 Tauri 2＋React 19 的 Agent Development Environment。Herdr 負責持續執行的 terminal／agent runtime；桌面端將它與 Editor、Git、Database、SSH/SFTP、Preview 整合。這是一個已有功能分層的 ADE。

Herdr serverNamed Session → Workspace／Tab／Pane；持有 PTY、process、agent identity。
Rust serviceHerdrManager、schema/capability、snapshot/events、terminal connector。
Typed IPC＋BridgeherdrIpc / herdrTypes → HerdrBridge → per-session Zustand store。
桌面工作面Spaces、Agents、Attention、Inspector、terminal layout 與其他工具。

Unix 使用 local socket、Windows 使用 named pipe。AppShell 管理版面，Bridge 處理 runtime 事件與跨 store 協調；狀態依 Named Session 隔離。關閉 Yuzora 時釋放自己持有的 connector，不停止 Herdr server 或 pane processes。[4] [5] [6]

Editor／LSP／搜尋CodeMirror 6 編輯；LSP diagnostics、completion、hover、rename、symbols、code actions；專案文字搜尋與分組結果。[12]

應保留的設計邊界

  • 身份分離：Named Session 是 runtime namespace；Terminal Session 是終端互動生命週期；Agent Session 是 coding agent 自身的語意對話／恢復身份。UI 不能把 tab、pane 或 terminal ID 當成 agent session ID。[4]
  • 權限與能力分離：terminal 的 observe/control 模式及 observer/controller 角色已有明確型別；操作受實際 schema、session 與 connector 狀態約束。[5]
  • Windows/WSL：Windows-native Herdr 擁有 runtime。WSL shell 不是另一個 Herdr runtime；目前 WSL Pi plugin 屬 Experimental，啟用與 adapter 操作為顯式流程，不能推廣成所有 WSL agent 都可 control/resume。[4]

② Herdr 0.8.2 功能全貌

官方設計的重點是持續執行、以滑鼠為先、能辨識 agent 狀態、可由 CLI／socket API 操作。使用者離開 client 後工作持續；介面應讓人找到需要處理的 agent，不必逐 pane 巡查。Named Sessions 是完全獨立的 namespace，官方建議多數人從一個 default session 開始。[2]

能力群功能與重要語意對桌面介面的含義
持續執行／恢復Detach／reattach、Named Sessions、restart layout/history recovery、agent-native session restore、live handoff；不同恢復路徑保留的資料不同。清楚分辨 client reconnect、server stopped、layout restore、agent resume；不能一律叫「重啟」。
Workspace／Tab／Pane建立、列出、聚焦、重新命名、關閉；Workspace/Tab 排序；pane split、swap、move、zoom、resize、neighbor/edges。跨 Workspace 移動 pane 會回傳新 public ID。保留 server 權威 topology、焦點與 identity；操作後使用回應中的 ID。
LayoutBSP tree、layout export/apply、split ratio；apply 是重建結構，不保留活躍 PTY／scrollback／process。需要區分「調整目前版面」與「套用新佈局」。不能將 apply 包裝成無損還原。
TerminalAttach、observe/control connector、input/text/keys、run、output wait、read source（visible/recent/recent-unwrapped/detection）、text/ANSI、scrollback、title。看得到／能輸入／擁有控制權是不同狀態；需要可靠 resize、scroll、重連及輸出呈現。
Agent 操作List/get/explain/focus/rename/read/start/prompt/wait/send-keys/attach；prompt/wait 綁定已辨識 agent。Blocked agent 的 prompt 會被拒絕。GUI 派工不能只模擬 terminal 打字；要呈現忙碌、需回覆、不可操作及完成結果。
Agent 狀態／偵測working、blocked、idle、done、unknown。done 代表 idle 且未查看，不等於任務成功；unknown 不能視為完成。整合可能提供 lifecycle、native session 或兩者。狀態保留語意與來源；不要把裝了 integration 當成所有 state/restore 都可靠。
Agent view／metadata宣告式 filter/sort、seen/status/context、pane/workspace tokens、display labels、TTL、authority guard；展示 metadata 不改變 lifecycle 權威。支援高密度掃描與篩選；不能因自訂 badge 改變等待或通知邏輯。
Events／通知Snapshot bootstrap、typed events subscribe/wait、agent status、layout、worktree、output/scroll changes；notification.show、sound、delivery/position。區分資料新鮮度、待處理狀態與 notification 送達結果；重連重新 snapshot。
Git worktreeList/create/open/remove；與來源 repo、branch 和 workspace 有關聯；remove 不會刪除 branch。建立隔離工作、開啟現有工作與移除 checkout 要有完整流程；關閉 Space 不可暗示刪除 worktree。
IntegrationsInstall/status/uninstall；agent lifecycle hooks、native session reference、restore 支援依 agent 而異。呈現支援表、安裝狀態與能力限制，保留使用者對 runtime/config 變更的掌控。
PluginsGitHub install、本機 link、build、enable/disable、uninstall/unlink、actions、startup/events hooks、logs、config/state directories、link handlers。需要 registry/provenance、platform/min-version、警告與錯誤、action/context 和 logs 入口。
Plugin panes／popupOverlay、popup、split、tab、zoomed；popup 是 session 級模態 surface，沒有 pane ID，與一般 pane/agent API 不同。不能只用普通 terminal pane renderer 就宣稱支援所有 plugin UI。
實驗性圖形pane.graphics info/set/clear/stream；需 kitty_graphics 開關；stream 的 ownership、大小限制與衝突需處理。xterm 文字顯示不等於 plugin graphics 支援；應明確降級而非默默缺圖。
設定／鍵盤／主題Config check/default/reset-keys/reload、prefix/navigate modes、可配置快捷鍵、theme、sidebar/tab bar、shell、notifications、scrollback。沿用 Herdr 心智模型，桌面快捷鍵需避免 OS/terminal 衝突；不需照搬 TUI 每個設定。
維運／更新／遠端Status、manifest status/reload/update、server stop/live handoff、stable/preview channels、自我更新入口、shell completion、remote client/SSH 工作模式。區分本機和遠端 authority；Yuzora SSH/SFTP 不等於完整 Herdr remote runtime 管理。

③ UI/UX 是否滿足 Herdr 設計？

若目標是「Herdr 的桌面 ADE 工作面」，目前方向成立；若目標是「完整替代 Herdr TUI/CLI 的圖形化控制台」，仍需補功能。API 沒有 GUI wrapper，不等於使用者在 terminal 內無法執行；這裡評估的是產品介面是否有明確、可完成的操作流程。

設計需求判定目前狀態與差距
Space → Agent → Terminal核心滿足Space rail、Agents、Attention、跳轉 owning pane/Space、read-only Inspector 與 terminal 已接通。[7]
Session 身份與隔離核心滿足Named Session selector、running/stopped、per-session snapshot/capability，避免跨 session 借用狀態。[6]
持續執行／多 client架構滿足server 擁有 process；Yuzora connector 有 observer/controller/takeover。今天未重測 detach/reconnect 或多 client 搶控制權。[5] [8]
Tab／pane layout主要操作滿足Create/rename/close/split/zoom/swap/ratio 等已實作；部分入口集中右鍵選單。完整 pane move、layout apply/模板等尚非現有 GUI 功能對等範圍。[9]
Attention單 Session 滿足；跨 Session 有缺口目前主要 poll／event subscription 與顯示限 selected session，背景 Named Session 沒有全域待辦聚合。這是 Yuzora 多 Session UX 的補強需求，不宣稱 Herdr 原生跨獨立 runtime 聚合。[6] [7]
Agent 操作閉環部分Catalog/create/get/read/inspect 已有；缺完整 prompt/wait/send-keys、attach/resume、explain 的 GUI 流程。Read-only Inspector 是現行設計，不是其本身出錯。[5] [7]
Worktree部分Inventory/provenance 可讀；缺 Herdr create/open/remove checkout 的完整 GUI 流程。既有 Git 頁不等同 Herdr worktree lifecycle。[10]
Integrations／Plugins特定整合滿足；通用管理有缺口WSL Pi 有專用 experimental 設定；不是通用 plugin registry/actions/logs/panes/graphics manager。[4] [11]
能力／錯誤／恢復防呆已有；恢復入口可加強Unsupported、stopped、error、disabled reason、empty onboarding 已有。需把 connecting、stale、版本不符及下一步說清楚；不能用「重啟」一鍵無條件停止別人的 server。
滑鼠與鍵盤有基礎；可發現性待改善Context menus、Radix、TerminalDrawer 的 roving tabindex 與 Arrow/Home/End 已有。需驗證完整 Herdr pane traversal，不能把 drawer tab keyboard 支援視為全 app 可及性通過。[9]
高密度／窄窗／視覺待實機驗證Session pills、Space label 與 agent status 用字很小，technical diagnostics 長。既有截圖只證明少量 agent 與特定尺寸；不能推出大量 agent、200% zoom、窄窗或螢幕閱讀器已可用。
Remote／維運／TUI 設定子集／產品範圍差異部分應保持由 Herdr CLI 處理。是否加入完整 remote、server lifecycle、theme/keybinding config、notification/graphics，應依產品定位決定。

建議改善順序與驗收條件

以下是研究建議，未開始實作，也沒有替專案建立新的 ADR 或功能承諾。

順序觸發情境 → 影響最小改善可驗收結果
1 · 多 Session 可見性使用者停在 A，B 的 agent 進入 blocked；目前可能需切回 B 才發現。Session pills 顯示待處理數、更新時間／stale；若產品要跨 session 監督，再加入全域 Attention 和有界背景更新。兩個 session 的測試 agent 分別進入 blocked/done；前台可辨來源、可跳轉正確 pane，並區分已讀與 stale。
2 · Agent 操作與恢復看見 agent 後，想續接、派工或解釋 unknown，仍需自行知道 CLI。以 capability 驅動 prompt/wait/attach/explain；把跳回 terminal 與結構化 action 都放在清楚位置。支援版本可完成一輪派工；blocked 時不送入 prompt；agent 被替換不誤完成原 wait；不支援時提供原因。
3 · 故障狀態的下一步Stopped、events stale、binary/schema mismatch 看起來都像「不可用」。狀態→原因→受控 action（重新連接／刷新／開啟診斷）；對 server stop/upgrade 保留明確 ownership。斷線、server停止、protocol不符各自有正確提示；恢復後 snapshot/layout/控制權不跨 session 混用。
4 · 常用 pane 操作可發現性初次使用者不知右鍵才能找到 split/zoom/swap。Terminal header 增加常用操作入口與快捷鍵提示，沿用現有 shadcn primitive 與 context menu。不依賴記憶快捷鍵也能 split→focus→resize→zoom→還原；鍵盤可達，焦點與結果清楚。
5 · Worktree 完整流程可看到 branch/provenance，卻無法直接為新任務建立或打開 Herdr worktree。先做 create/open；再做有 dirty/process/context 說明的 remove。Workspace canonical path、branch/base 和 checkout 對應正確；取消不產生變更；移除不誤刪 branch。
6 · 資訊階層與通用擴充大量 agent／長 session 名稱與 diagnostics 增加掃描負擔；plugin 功能只能靠 CLI。先改善文字尺寸／截斷與狀態文字，將診斷細節折疊；再視需要增設 Plugins & Integrations 工作面。窄窗與高 zoom 保留關鍵 status/action；unsupported plugin 呈現原因，錯誤與 logs 可追溯。

不建議為了「功能對等」立即把所有 Herdr raw API 做成按鈕。先補常用工作流程；advanced graphics、layout apply、server live handoff、完整 config editing 可以維持進階入口，前提是支援邊界和操作方式清楚。
