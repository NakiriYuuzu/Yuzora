Yuzora ADE · Herdr Skill Review

從 Terminal Workbench 升級為 Agent Control Plane

目前 Yuzora 已完成 Herdr named sessions、Spaces、Agents 投影、typed terminal pages、BSP panes、control/takeover、focus restore 與 destructive-action safety。對照 $herdr skill 後，下一個最大缺口不是更多 terminal chrome，而是 Agent automation、attention inbox、event stream、background Runs 與 artifact semantics。

建議採「Agent Control Plane first」，再往 Mission／Task／Run 擴張

三種演進方向

A. Terminal parity first

把更多 Herdr commands 放進 context menu 與 command palette。

  • 最快交付
  • 但容易成為另一層 TUI wrapper
  • 缺少 ADE 的任務與結果語意

B. Agent Control Plane first（推薦）

先接事件流、Agent prompt/wait/read、blocked/done inbox，再建立 durable Runs。

  • 直接補齊最大產品缺口
  • 可沿用現有 terminal pages
  • 為 Mission／Task／Artifact 建立可靠底座

C. Mission model first

先建立 Yuzora Mission／Task／Run domain，再向下綁 Herdr。

  • 產品敘事最完整
  • 但 event 與 Agent automation 未穩定時容易做出假狀態
  • 重工風險最高

推薦 Roadmap

P0 Event-driven Agent Inbox

  • 實作 named-session-aware events.subscribe consumer，斷線後以 cursor／revision resync。
  • 事件健康時停止 4 秒 polling；事件中斷時自動回退 bounded polling。
  • 把 blocked、done、runtime error 聚合成「Needs attention」。
  • 讀取 output 不應 mark seen；只有 focus Agent／Tab 才清除 done badge。

P0 Agent Automation Contract

  • Rust typed wrappers：agent get/prompt/wait/read/send-keys。
  • 以 named session env 路由；使用 public CLI，不重做 private protocol。
  • Agent command target 優先使用 explicit paneId；不可使用目前 frontend 的 terminal-based agent.id。
  • 完整呈現 agent_prompt_stalled、blocked、timeout 與 unsupported capability。

P1 Agent Inspector

  • Agents row 保留 terminal activation；另加 Inspector／context menu actions。
  • 內容：狀態、Space、Tab、Pane、cwd、Prompt、Wait、Read、Esc、Ctrl+C、Focus。
  • Prompt 預設 --wait，完成於 idle／done／blocked；不自行猜測完成。
  • blocked 時顯示需使用者處理，而非當成失敗或完成。

P1 Durable Runs

  • Agent Run：綁定 agent prompt --wait。
  • Command Run：綁定 pane run + wait-output。
  • 保留 target IDs、started/settled timestamps、timeout、result source 與 artifact refs。
  • Run 是 Yuzora domain；不要把 terminal scrollback 偽裝成 conversation history。

P1 Smart Spawn

  • 先檢查 pane 是否為 available interactive shell，再允許 agent start。
  • 依 pane geometry 選 right／down；保留 cwd；background 預設 --no-focus。
  • 使用 shadcn Dialog／Command／Select 選 agent kind、唯一名稱與 native args。
  • 建立、split、start 是分離步驟，失敗時不得留下虛假的 Agent row。

P2 Output、Artifacts、Worktrees

  • Output Inspector 支援 visible／recent／recent-unwrapped／detection 與 ANSI。
  • alternate-screen 無法回讀時，明確要求 Agent 輸出 artifact file，再由 Yuzora 收錄。
  • Space 顯示 worktree metadata；Agent Spawn 可選既有 worktree context。
  • done／blocked 可觸發 Yuzora notification center 或 OS notification。

建議資料流

Herdr event / CLI→ Rust typed automation + event service→ snapshot/event reducer→ Agent Inbox + Inspector→ Yuzora Run→ Artifact／Notification

現有 NDJSON API 繼續負責 snapshot、resource 與 layout；terminal connector 繼續負責即時 xterm；Agent／Pane automation 則以 installed Herdr public CLI 建立獨立 typed lane。三者不可混成一個巨型 transport。

需要先修正的語意邊界

  • Agent identity：目前 normalized agent.id 是 terminalId ?? paneId；Herdr skill 明確指出 Agent command 不接受 terminal ID。Automation DTO 應新增 explicit commandTarget，protocol-19 預設使用 pane ID。
  • Focus ownership：Herdr global focused pane 可能由 TUI 或另一 client 改變。建議提供「Follow Herdr Focus」政策：冷啟動恢復一次；使用者本機操作後預設 pin local view，除非主動開啟 follow。
  • Status：done 不是另一種 idle 顏色，而是「背景工作完成、尚未看過」；unknown 也不能被當成完成。
  • Read vs focus：讀 transcript 不 mark seen；點擊 Focus 才改變 runtime focus 與 done semantics。
  • Stopped sessions：維持現行誠實顯示，Automation actions 全部 disabled，不偷偷 attach 或 start server。

建議第一個實作 tranche

「Herdr Event Inbox + Agent Inspector Read-only」：先接事件流與 agent get/read，完整呈現 blocked/done/unknown、output sources 與 follow-focus policy；暫不提供 prompt/start。這一 tranche 風險最低，卻能驗證 identity、event recovery、seen semantics 與 UI information architecture，之後再開啟 mutation actions。

不建議第一步直接做 Mission／Task，也不建議一次加入所有 Agent commands；先把事件與 read-only truth 做準確，才能避免 ADE 顯示「看似完整、實際與 runtime 漂移」的假狀態。
