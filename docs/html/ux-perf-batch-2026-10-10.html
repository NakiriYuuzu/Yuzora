1. Claude Code 人偶（Clawd）

根因

  • 內嵌的 @fontsource-variable/jetbrains-mono 子集不含 U+2580–U+259F，本機也沒有安裝 JetBrains Mono，所以 ▐▛███▜▌ 這類字元會落到 PingFang TC 等 CJK 字型，字寬和字高都對不上 cell。
  • xterm 6 只有 DOM renderer，customGlyphs（xterm 自繪方塊字元）在 DOM renderer 下不生效。
  • 過去沒有任何針對這個問題的修復；bb54e559 只處理 Windows 的字寬。

修法

  • 擴充既有的 bun patch patches/@xterm%2Fxterm@6.0.0.patch，同時改 TS 原始碼與兩個 minified bundle：U+2580–U+259F 的 cell 各自輸出成一個 span，文字是空白，寬度剛好一格，並帶 xterm-block-<hex> class。
  • 新增 src/terminal/xtermBlockGlyphs.css，以 currentColor 漸層圖層畫出全部 32 個字元：八分之幾高寬的條塊、象限與陰影；不覆蓋 cell 背景色。SGR 8 隱藏的 cell 維持不畫。
  • fixture fixtures/xterm-block-glyphs.html 可用於日後升級 xterm 時複驗；patches/README.md 已記錄做法。

點擊

  • 以 PTY 實測 Claude Code 2.1.295：
    • 預設模式（使用者設定 "tui": "default"）完全不開啟 ?1000/?1002/?1003/?1006，所以 Clawd 在任何終端機都點不動，這是 Claude 本身的限制。
    • fullscreen 模式（/tui fullscreen 或 CLAUDE_CODE_NO_FLICKER=1）會開啟這些滑鼠回報。
  • Clawd 的 onClick 會隨機播放 14 種動畫之一，已在 binary 中確認。
  • Yuzora 0.0.18 的點擊轉送本來就正確。這次新增的是 hover 轉送：
    • 只對偵測到 Agent 的 pane 生效，需要 HERDR 0.9.3 以上。
    • 遠端 helper 以新的 hello 旗標 herdrTerminalMouseMove 協商，舊版 helper 不會收到 move，避免整條串流被中斷。

實機點擊證據：以隔離 HERDR 的 pane read 當 oracle，每 120 ms 取樣一次。點擊前 30 次取樣都是靜止影格；點擊後連續兩次點擊都出現多個動畫影格，包括 ▗▟▛███▛█▄（舉手）、▐▂███▂█（閉眼）與 ·／~ boop 粒子。假 TUI 記錄到每次點擊都完整收到 ESC[<0;16;4M 和 ESC[<0;16;4m。

2. Finder／檔案總管 → 側邊欄

  • 原本 Finder 複製、檔案樹貼上已在 v0.0.17 出貨，但只在焦點位於樹的某一列時生效。真正缺的是 OS 拖放：Tauri 原生拖放層會吞掉 HTML5 drop。
  • 拖放的落點規則：
    • 落在資料夾：複製到該資料夾
    • 落在檔案：複製到該檔案所在的資料夾
    • 落在空白處：複製到工作區根目錄
    拖曳時會標示目標，完成後展開資料夾並選取匯入的項目，同名檔案自動改名。
  • 信任模型：
    • Rust 只記錄 main webview 最近 3 次原生 Drop 的路徑，有效期 120 秒。
    • 匯入時，renderer 傳來的路徑必須完全符合其中一次 drop，成功後該次授權即作廢，無法重放。
    • renderer 無法讓 Rust 讀取任意檔案。
  • WSL：
    • 新增 host 操作 FilesImport，帶 hello 旗標，只能由 Rust 指令發送，renderer 的 host_request 會拒絕。
    • 授權與前置檢查（WSL 開關、連線目標、helper 版本）都在消耗授權之前完成。
    • 路徑轉換：wslpath 會把 C:\x 轉成 /mnt/c/x；同一發行版的 \\wsl.localhost\… 直接對應。其他發行版、其他 UNC share，以及只拖發行版根目錄，都會回報明確錯誤。
  • SSH 工作區：拖放維持原本的「在編輯器開啟」；貼上 OS 檔案時顯示「暫不支援」。
  • 檔案樹空白處按 ⌘／Ctrl＋V 會貼到根目錄。

未實機驗證：跨 app 的 Finder 拖放無法由 CUA 自動化，需要使用者手動驗收；Windows 與 WSL 只有單元測試覆蓋。

3. HERDR 動作（方案 A）

  • 首頁先問「你想做什麼？」，列出 6 張任務卡，下方是進階列（整合、外掛、通知設定）；不可用時直接寫出原因。
  • 頂端固定顯示「作用於：主機 › Session」，符合 ADR 要求的明確選取。
  • Agent 分成兩個任務：
    • 「啟動 Agent」：名稱自動產生，常用 6 種 Agent 排在前面，其餘收在「更多…」，名稱與參數收在「進階」。
    • 「傳訊息給 Agent」：送出按鍵、等待狀態與診斷都收在「進階」。
  • 入口：
    • 側欄扳手開啟首頁
    • Space 右鍵進入 Worktree
    • Pane 右鍵依是否已有 Agent，進入「啟動」或「傳訊息」
    • ⌘K 新增 7 個命令，作用的 Session 與側欄一致
  • 通知開關移到「設定 → HERDR」。
  • 型別化操作與參數完全不變，Rust 與 herdrFeatures.ts 都沒有改動，舊有的每個功能都仍可到達。

風險與後續

  • Finder 拖放需要使用者手動實機驗收；Windows／WSL 的拖放與貼上只有單元測試，需要在 Windows 實機或 CI 驗證，而且要重新部署同版本的 helper。
  • 在 Yuzora 外啟動或停止的 Session，最多約 16 秒才會反映到側欄（原本約 4 秒）。
  • HERDR 不保留 SGR 8（隱藏文字），隱藏的字元會照常顯示。這是既有行為，不是本次造成的。
  • 未完成或延後：
    • Git：S3（相同 status 不更新 store），因為 diff reload 依賴 statusRevision；index-only 事件不重載分支
    • HERDR：隱藏分頁暫停解碼、HerdrScrollbar 只在有活動時更新、bootstrap 時不清空 capabilities
  • CHANGELOG 新增了 [Unreleased] 段落。repo 過去沒有用過這種段落，release 時要改成版本號。
