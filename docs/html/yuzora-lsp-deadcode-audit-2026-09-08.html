02 / LSP 缺口與優先順序

P2 · 自動重啟 server 後，client 沒有重新握手

後端 watch_loop 在未達 restart limit 時重新 spawn child；成功 respawn 沒有通知前端重建 LSPClient。ensureClient 仍回傳快取，LspBridge 的狀態事件只更新 store。若 server 閒置期間退出並成功重啟、未先觸發 send failure，新 server 會失去 initialize 與已開啟文件狀態。

建議驗收：受控 server crash 後，確認新程序依序收到 initialize、initialized、目前文件 didOpen，並恢復 completion 與 diagnostics。此情境本次僅做 source 追查。

src/lsp/lspManager.ts:80、src/workbench/LspBridge.tsx:30、src-tauri/host/src/lsp_service.rs:485。傳送失敗時已有另一條 stopWorkspace 路徑，不能把所有 crash 情況概括成必然掛住。

P2 · Quick Fix 可見，但 command-only／空結果會靜默無效

每個 pull diagnostic 都產生可點的 Quick Fix。codeActionsFor 只保留 title、kind、edit；apply callback 只找帶 edit 的結果。server 回傳空結果或 command-only action 時，按下後不執行命令，也不回報無可用修正。多個 edits 選項則直接挑第一項，沒有供使用者選擇的流程。

src/lsp/codeActions.ts:68、src/lsp/codeActions.ts:137、src/lsp/codeActions.ts:143。

P2 · 跨檔 Code Action 可能只套用一部分

applyWorkspaceEdit 先過濾 c.uri === uri，其他文件的 edits 被捨棄。涉及多檔的修正可能只改到目前檔案，形成不完整結果。應套用完整工作區 edit，或明確拒絕不支援的整組變更。

src/lsp/codeActions.ts:79。此限制是診斷 Code Action 路徑；一般跨檔 Rename 的文字 edits 有另一條 YuzoraWorkspace 更新路徑。

功能缺口 · WorkspaceEdit 的檔案操作被過濾

workspaceEditToChanges 只接受 TextDocumentEdit。CreateFile、RenameFile、DeleteFile 不會成為文字 changes；使用到此轉換路徑的 action 無法完成這些檔案操作。不能以目前的文字 Rename 支援推論完整 resource operations 支援。

src/lsp/renameCompat.ts:40。

功能缺口 · pylsp 無法 managed install

設定中可選 pylsp，但 catalog 將所有平台設為 unavailable，原因是完整 reviewed dependency content manifests 尚未完成。這是已宣告的供應限制；不代表已由外部安裝的 pylsp 一定不能啟動。

src/app/workbench/LspSection.tsx:53、src-tauri/lsp-catalog/manifest.json:221。
