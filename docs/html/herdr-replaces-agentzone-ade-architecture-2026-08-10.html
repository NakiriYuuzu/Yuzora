修正後結論：前一份 No-Go 已失效

如果下一版 Yuzora 不再是 IDE，而是 ADE，那麼「保留 ACP AgentZone rich chat」就不應再是架構限制。原本被我視為損失的部分——chat transcript、ACP permission modal、session config chips——現在應重新判斷為「舊 IDE/assistant paradigm 的 UI」，不是必須保留的產品核心。

新的結論：Herdr 完全取代 AgentZone 是可行且方向一致的。依最新澄清，不需要重畫整個 shell：保留現有 AppShell、rail、ProjectNavPanel、tab bar 與 editor group 視覺架構，將核心 page content 改為 Herdr terminal，並以 native React UI 投影 Herdr Spaces/Agents。
仍然成立的限制：Herdr 不是完整 ADE。它解決 PTY ownership、agent detection、persistence、workspace/tab/pane 與 terminal automation；Mission、Task、Run correlation、Artifact、Policy 與 Review semantics 仍要由 Yuzora 建立。

最終導覽決策：ADE 取代 Files 的第一順位

本文將使用者的最終想法解讀為：刪除舊 ACP AgentZone；以 Herdr-native ADE surface 取代它；並把這個新 surface 放到 Yuzora 五個主要 modes 的第一位，取代目前 Files 的預設位置。Files 不必消失，但降為第二順位的 artifact inspection surface。

評估：同意。這是從產品資訊架構上真正完成 IDE → ADE 轉型的必要動作。只把 Agent icon 從第五格搬到第一格不夠；DEFAULT_MODE、空白啟動頁、workspace rail、project sidebar 與中心 surface 都必須改以 Herdr runtime state 為入口。

Herdr sidebar 的 Yuzora 對應

Herdr expanded sidebar 本質上分成 Spaces 與 Agents 兩區。Yuzora 的 ADE nav 應直接採同一個 domain，而不是繼續使用 ACP session list：

  • Spaces / Projects：顯示 active Herdr session 中的全部 workspaces，維持順序、focus、worktree parent/child、branch、git status 與 rolled-up agent state。
  • Agents：顯示全部 workspace/tab/pane 中的 agents，支援 grouped/priority、blocked/working/done/idle、focus、rename、prompt 與 terminal attach。
  • Workspace rail：現有 Recent Workspace tiles 不再是 source of truth；改為 Herdr session/runtime indicator 或移除重複 project list。Recent history最多只保留 disconnected/offline 開啟用途。
  • Main surface：點 Agent 開 Run/Terminal；點 Space 切換 Yuzora 的 active project context，Editor/Git/DB/SSH 隨之綁定該 cwd。

直接移除舊 AgentZone 的工程判斷

產品上可以直接移除，不提供 legacy mode；工程上仍應先建立可編譯的替代 vertical slice，再刪除舊 modules。目前至少 22 個 production/test files 直接引用 agentStore/useAgentStore，WorkspaceRail badges、context menu、Settings、Bridge 與大量 AgentZone tests 都會被影響。合理順序是：

  1. 先建立 HerdrRuntime、snapshot cache、ADE store 與最小 Spaces/Agents UI。
  2. 把 DEFAULT_MODE 改為 ADE，移除舊 AgentZone 的產品入口。
  3. 把 WorkspaceRail agent counts、context menu 與 command palette 改接 Herdr。
  4. 同一變更系列內刪除 ACP AgentZone、AgentBridge、agentStore、router/adapter 及舊 tests。

這不是保留雙架構，而是避免在替代物尚未可啟動前把主分支切成不可編譯狀態。

最終澄清：不嵌 Herdr TUI，只顯示目標 Terminal Page

本文將最新想法解讀為：Yuzora 不顯示 Herdr 自己的 sidebar、tab bar 或完整 TUI；Herdr Spaces 與 Agents 改由 Yuzora sidebar 原生渲染；中心 page 則直接顯示被選 Herdr pane/agent 的 terminal frame。這個方案可行，而且比嵌入完整 Herdr TUI 更符合現有 Yuzora 設計。

Page model

目前 TabInfo 只有 file/preview，應擴成 discriminated union，而不是讓 terminal 假裝成檔案路徑：

type WorkbenchPage =
  | { kind: "file"; id: string; path: string }
  | { kind: "preview"; id: "preview" }
  | {
      kind: "herdr-terminal"
      id: string
      sessionId: string
      terminalId: string
      paneId: string
      workspaceId: string
    }

terminalId 應作為 live terminal identity：Herdr 的公開 PaneInfo 同時提供 pane_id 與 terminal_id；pane 跨 workspace move 時 public pane id 可能改變，但 running terminal identity 可維持。所有 identity 仍需加上 Herdr session namespace。

使用者操作

  • 點 Agent：以該 agent 的 terminal_id 開啟或聚焦 Herdr Terminal Page。
  • 點 Space：切 selected workspace；可預設開啟該 Space 的 focused pane。
  • 按 ＋：在 selected Space 建立新的 Herdr tab/root pane，再開成 terminal page；下拉選單可增加 Launch Agent。
  • 打開檔案：沿用 Editor page，與 terminal pages 共用同一 tab bar/editor group。
  • 關閉 page：只送 terminal.release/關閉 connector，不關閉 Herdr pane 或 agent process。
  • Terminate Pane：必須是獨立且明確的 destructive action，才呼叫 pane.close。

Terminal transport

不要在 xterm 裡執行普通 herdr 指令，否則會再次顯示 Herdr TUI。應由 Rust 啟動 connector：

  • herdr terminal session observe <terminal-id>：read-only。
  • herdr terminal session control <terminal-id>：可輸入。
  • stdout NDJSON：terminal.frame／terminal.closed。
  • stdin NDJSON：terminal.input、terminal.resize、terminal.scroll、terminal.release。

現有 TerminalSession.tsx 的 xterm、FitAddon、IME、clipboard、theme 與 output queue 可保留；只需把 ptyOpen/write/resize/close 抽成 transport interface，再增加 HerdrTerminalTransport。

Herdr 尚缺的 ADE 關鍵語意

G1. 沒有 durable Mission / Task / Run model

Herdr 有 workspace/tab/pane/agent，沒有「這個 agent 為哪個目標工作、成功條件、產出、決策、父子任務」。Yuzora 必須自己擁有這個 domain；不要把 Mission 假裝成 tab label 或 metadata token。

G2. agent.prompt --wait 不追蹤 individual turn

官方文件明確指出：若 agent 已在 working，當前 turn 完成就可能滿足 wait。對 ADE orchestrator，這代表不能把 Herdr wait 當可靠的 RunCompleted(runId)。短期只對 idle agent dispatch，並由 Yuzora 保存 correlation；中期應推動 Herdr 增加 turn/run correlation primitive。

Herdr docs/agent-automation.mdx:72-80

G3. Lifecycle detection 不是業務成功

idle/done/blocked/working/unknown 只能說 terminal agent 的 UI 狀態；不能表示 Task acceptance criteria 通過。Blocked screen detection 也刻意保守，新 prompt 可能 fallback 成 idle。Yuzora 的 Run state 必須區分 runtimeState 與 outcome。

Herdr docs/agents.mdx:38-60；docs/agent-automation.mdx:76-80

G4. Metadata 與 Agent View 不足以當 durable ADE state

Herdr tokens 在 server restart 後不恢復；Agent View 也只維持到 clear/replace/plugin disable/server exit。因此 summary/model/role 可以投影到 Herdr metadata，但 durable truth 必須保存在 Yuzora。

Herdr docs/socket-api.mdx:450-475, 734-778

核心判斷：這四個缺口不是反對 Herdr，而是清楚劃分深模組：Herdr 管 execution runtime；Yuzora 管 ADE semantics。這正是 Yuzora 仍有存在價值的地方。

應建立的深模組與最小 Interface

HerdrRuntimeInterface 應維持小：connect()、snapshot()、dispatch()、attach()、control()、subscribe()、shutdownClient()。內部隱藏 protocol、socket、CLI connector、reconnect、seq、ownership 與版本。
AdeOrchestratorcreateMission()、dispatchTask()、recordDecision()、completeRun()。它不應暴露 Herdr pane IDs 給 UI 作為業務 identity。
ArtifactIndex以 workspace/worktree watchers、Git status/diff、agent-reported paths 建立 artifacts 與 changes；取代 ACP transcript diff 作為權威。
PolicyGate把 runtime blocked/terminal prompts、destructive action、worktree remove、external command 等統一成 ADE decision requests。
Seam 原則：React 不學 Herdr protocol；Mission domain 不依賴 w1:p2；Herdr adapter 可被 fake runtime 替換做單元測試。這樣 Herdr upgrade/fork 不會污染整個 UI。

安全遷移：Replace，不要 Layer Forever

M0 · Contract
固定最小 Herdr vertical slice定義 runtime snapshot/cache、Space/Agent identity、selected project 與 terminal attachment contract；確認 protocol/turn-correlation 邊界。
M1 · Kernel
Bundle Herdr＋建立 HerdrRuntimeYuzora namespace、daemon lifecycle、snapshot/events、terminal observe/control、protocol gates、Windows/macOS/Linux packaging。
M2 · Replace Nav
ADE 取代 Files 的第一順位Herdr Spaces＋Agents 取代 ACP session nav，DEFAULT_MODE 切為 ADE；Files 移到第二順位。
M3 · Remove ACP
同一變更系列刪除舊 AgentZone移除 AgentBridge/agentStore/acpConnection/router/builtin adapter、WorkspaceRail 舊 badges、context-menu routes 與舊 tests，不提供 legacy mode。
M4 · ADE Domain
Mission/Task/Run persistence加入 correlation、launch profiles、worktree binding、artifact/change index、policy decisions；所有新能力只建在 Herdr path。
M5 · Harden
跨平台與 recovery驗證 daemon upgrade、snapshot reconciliation、named sessions、remote、ownership conflicts、external focus 與 cold restore。

粗估：能取代 AgentZone 的本地 ADE alpha 約 6–10 週；包含 bundled runtime、跨平台、worktree orchestration、migration、hardened recovery 的 production release 約 12–20 週。這已是產品主版本重構，而不是 feature integration。

建議優先推動的 Herdr upstream 能力

  1. Correlated agent run/turn：agent.prompt 回傳 run token；事件與 wait 可綁該 token，不被既有 active turn 誤滿足。
  2. Durable metadata namespace：可選擇在 restart/handoff 後恢復 Yuzora-owned role/run/mission references，或至少提供安全 replay hook。
  3. Stable headless terminal bridge contract：正式文件化 frame sequence、full resync、ownership conflict、reconnect 行為與跨版本承諾。
  4. Lifecycle integration coverage：讓主要 agent 以 hooks/plugins 提供可靠 working/blocked/idle，而不是只靠 screen manifest。
  5. Remote control-plane bridge：不只整個 TUI remote attach，也能安全代理 snapshot/events/terminal session 給第三方 desktop client。

Herdr 已是 Apache-2.0。策略順序應是：先用公開 interface → 提 upstream PR → 必要時維護最小 downstream patch；避免長期 fork 整個 terminal runtime。

產品級風險

變成 GUI Herdr
若 Yuzora 只重畫 workspaces/panes/sidebar，就沒有產品護城河。必須把 Mission、Policy、Artifact、Review 做成第一級 domain。
狀態誤判
Herdr idle/done 不等於 task success。UI 與資料模型必須明確分離 runtime state、run outcome、acceptance state。
Turn correlation
在 Herdr 增加 correlated run 前，不可做無人值守的複雜 DAG 自動派工；只能對 idle target 做受控 dispatch，並保留人工 review。
Bundle lifecycle
Yuzora 關閉不能殺 Herdr panes；更新不能讓舊 server/client protocol 卡死。需要 daemon ownership、live handoff/restart policy、namespace migration。
Windows maturity
Herdr 0.8.0 的 native Windows 仍是 beta/preview；Yuzora 若承諾三平台同等 ADE，需納入 upstream readiness 與 fallback。
ACP capability loss
usage/cost、structured permissions、image/config 等不再保證一致。這是有意識的產品取捨，必須以 ADE workflow 取代，而不是默默退化。
Replacement sequencing
不保留 legacy mode，但仍必須先有可編譯的 Herdr vertical slice，再於同一變更系列移除舊 core；否則會出現無 Agent 首頁或主分支不可啟動的空窗。

最終決策建議

GO：把 Herdr 定位為 Yuzora ADE 的必要 Agent Runtime Kernel，完整取代 AgentZone 的 process/session/lifecycle surface。
GO：移除 chat-first information architecture，改為 Mission → Task → AgentRun → Attention/Artifact/Change/Decision。
CONDITION：Yuzora 必須自己建立 ADE orchestration domain；不能只依賴 Herdr workspace/pane metadata。
CONDITION：在 production autonomous orchestration 前，解決 correlated run/turn 與 lifecycle reliability。
NO：不要在既有 AgentZone 上疊 Herdr adapter，讓兩套 session model永久並存；那會是最昂貴、最淺的架構。

新的產品敘述：Yuzora 不是「有 Agent 的 IDE」，而是「以 Herdr 為 execution kernel、以 Mission 與 Agent Fleet 為中心、由 Editor/Git/Terminal/DB/SSH 提供工作與驗收 surfaces 的 ADE」。
