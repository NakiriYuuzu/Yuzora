此版本已被產品方向澄清取代

本報告原先假設 Yuzora 仍是 IDE，且 AgentZone 的 ACP rich transcript 必須保留。使用者已於 2026-08-10 澄清：下一版 Yuzora 將轉型為 ADE，Herdr 的目標就是完全取代 AgentZone。因此本報告的「不取代 AgentZone」結論不再適用；請改讀 Herdr 取代 AgentZone：ADE 架構重估。其餘 Herdr socket、terminal stream、protocol 與安全證據仍可沿用。

Yuzora architecture study · Herdr 0.8.0

Herdr 能否深度綁定 Yuzora？

結論不是單純的「能／不能」，而是：可以深度整合成 Yuzora 的持久化 Terminal／TUI Agent runtime；不適合取代 Yuzora 現有 ACP AgentZone，也不應把 Herdr 直接嵌成 Rust library。

核心判斷

Herdr 與 Yuzora 的產品能力高度互補，但執行模型不同。Herdr 強項是「server 擁有真實 PTY、跨 client detach 後持續執行、辨識 TUI coding agents、提供 workspace/tab/pane/agent socket API」；Yuzora 強項是「桌面 GUI、Editor/LSP/Git/DB/SSH/SFTP、結構化 ACP transcript、permission/elicitation、diff 與檔案 buffer 協調」。

最值得做的深度綁定：讓 Herdr 成為 Yuzora 的 persistent terminal and terminal-agent runtime，由 Yuzora 提供 GUI 控制、狀態彙整、選定 pane 的 xterm 呈現，以及安全的 typed IPC。
不應做：把 Herdr 當成 Yuzora ACP session manager，或讓 Herdr 取代 AgentZone。Herdr 只看 terminal/pane lifecycle，沒有 ACP 的結構化訊息、tool call、permission、form elicitation、open-buffer edit 協調。

一句話決策：接受「雙 runtime、單工作台」；拒絕「單一 runtime 全盤接管」。

「深度綁定」應拆成三種層級

層級內容判斷
A. UI Link顯示 Herdr 是否運行、列出 workspaces/agents、點擊後開啟 Herdr TUI。容易，但不算深
B. Control-plane BindingYuzora 維護 session.snapshot cache、訂閱事件、建立／聚焦／分割 pane、prompt/wait agent，並在 xterm 中 attach Herdr terminal stream。推薦目標

為何技術上能深度整合

1. Herdr 已提供真正的外部 client surface

  • session.snapshot 一次回傳 version/protocol、workspace、tab、pane、layout、agent；外部 client 之後可用事件更新本地 cache。
  • Socket API 是 local Unix domain socket／Windows named pipe 上的 newline-delimited JSON，適合由 Tauri Rust backend 建立長連線。
  • 事件包含 workspace/tab/pane/layout、agent detection/status、scroll、worktree lifecycle；不必靠輪詢畫面。
  • 後續實作核對發現：本機已安裝 herdr 0.8.0 的 herdr api schema --json 回報 protocol: 19；本報告分析的較新 source checkout/schema 則是 protocol: 20。因此版本 gate 必須以實際選定 binary 的 schema/artifact 為權威，不能把 source checkout 的 protocol 值套到已安裝 binary。

Herdr: docs/.../socket-api.mdx:6-16, 36-46, 93-127, 637-678, 780-922；docs/next/api/herdr-api.schema.json

2. Herdr 已提供第三方 GUI 可用的 Terminal stream bridge

  • herdr terminal session observe <target> 以 NDJSON 輸出 base64 ANSI terminal.frame。
  • herdr terminal session control <target> 除了輸出 frame，也接受 terminal.input、terminal.resize、terminal.scroll、terminal.release。
  • 只有一個 writable controller；多個 observer 可並存。這恰好能對應 Yuzora「預設唯讀、使用者明確取得控制權」的安全 UX。

Herdr: docs/.../persistence-remote.mdx:103-152；src/client/mod.rs:930-1184；src/protocol/wire.rs:420-434

3. Yuzora 已有可重用的 xterm 與 Bridge 架構

  • TerminalSession 已封裝 xterm、resize、input、theme、IME、output queue；主要需要把後端從固定 pty* IPC 抽成 backend interface。
  • App.tsx 已採 *Bridge headless sibling 模式；新增 HerdrBridge 與既有架構一致，不必污染 AppShell。
  • Workspace rail 已能按 workspace 彙整 ACP agent counts；可新增獨立的 Herdr status projection，而不必重寫 rail。

Yuzora: src/terminal/TerminalSession.tsx:70-340；src/App.tsx:1-31；src/workbench/AgentBridge.tsx:15-103；src/app/workbench/WorkspaceRail.tsx:45-177

4. 安全邊界足以支撐本機整合

  • Herdr 的 Unix socket 檔案權限強制為 owner-only 0600。
  • 但 socket API 等同完整 terminal control；Yuzora 必須只在 Rust backend 暴露 allowlisted typed commands，不可讓 webview 任意透傳 method/params。

Herdr: src/server/socket_paths.rs:11-74；src/api/server.rs:27-135

真正的架構衝突

衝突一：Agent ownership

Yuzora 的 ACP adapter 由 Rust agent_process 以 pipe stdio 管理；Yuzora 直接取得 structured ACP updates。Herdr 則必須擁有 PTY pane 才能辨識／控制 agent。兩者不能同時擁有同一個 process 的 stdio/PTY。

硬證據：Yuzora 內建 Pi adapter 以 mode: "rpc" 綁 Pi extensions；Herdr 0.8.0 明確修正「Pi RPC、JSON、print processes 不再宣告 TUI pane lifecycle」，本機 Herdr Pi extension 也以 ctx.mode !== "tui" 直接退出。因此，現有 ACP sessions 不會、也不應自動成為 Herdr panes。

Yuzora: adapters/yuzora-pi-acp/src/session-host.ts:1019-1052；Herdr: CHANGELOG.md:58；~/.pi/agent/extensions/herdr-agent-state.ts:228-230

衝突二：Terminal layout model

Herdr 是 arbitrary BSP tree，可跨 tab/workspace 移動 live pane；Yuzora 的 TerminalWorkspaceLayout 是「tab list＋最多兩個 visible panes＋單一 split ratio」。若要求 1:1 呈現 Herdr layout，等於重寫 TerminalStore/Drawer。

Yuzora: src/state/terminalStore.ts:23-75, 122-417；Herdr: docs/.../socket-api.mdx:130-401

衝突三：App exit semantics

Yuzora 現在在 app exit 對 local PTY、process、ACP adapter、agent terminal、SSH 等執行 kill_all()；Herdr 的價值正是 Yuzora 關閉後 process 仍存活。Herdr connector 必須是獨立 manager，只關閉 observer/controller 子行程與 socket，不可停止 Herdr server 或 pane。

Yuzora: src-tauri/src/lib.rs:366-395；Herdr: docs/.../concepts.mdx:65-77；docs/.../session-state.mdx:19-29

衝突四：Workspace identity

Yuzora 以 canonical path 為核心且同時只開一個 active workspace；Herdr workspace 有自己的 ID、tab/pane tree，也可能是 worktree checkout。不可只用 label 對應。應建立 HerdrWorkspaceBinding，至少保存 Herdr session、workspace ID、identity cwd、checkout path 與 Yuzora canonical path。

建議新增的最小 domain objects

  • HerdrConnectionState：binary path、client/server version、protocol、socket、status、last error。
  • HerdrRuntimeSnapshot：以官方 snapshot 為來源，不把 Herdr 資料硬塞進現有 agentStore／terminalStore。
  • HerdrPaneAttachment：target、mode(observer/controller)、seq、size、ownership conflict、connector process id。
  • HerdrWorkspaceBinding：Herdr session/workspace ↔ canonical path/worktree checkout。
關鍵設計原則：先用 adapter/interface 讓 TerminalSession 支援 local PTY 與 Herdr stream 兩種 backend；不要一開始把兩個 store 合併成一個巨型通用模型。

Binary distribution：第一版連外部 Herdr，成熟後才考慮 bundle

建議 POC/P1 只連使用者明確選定、已安裝的 Herdr binary，顯示 absolute path、version、protocol 與 server compatibility。這能避免 Yuzora bundled Herdr 與使用者既有 Herdr server／session 發生版本或 socket namespace 衝突。若後續要求 one-click experience，再評估 bundled sidecar，並使用獨立 config/session namespace、固定相容版本、Apache NOTICE 與明確 updater ownership。

建議分階段路線

POC · 3–5d
證明可連、可看、可重連偵測指定 Herdr binary；做 version/protocol gate；抓一次 snapshot；訂閱 agent/pane/layout events；以 observer 在 xterm 顯示一個 pane。完全不做 mutation。
P1 · 1–2w
第一個可用版本新增 Herdr nav/view、workspace/agent badges、selected-pane viewer、controller ownership UX、input/resize/release、斷線 resnapshot、connector shutdown。仍不碰 ACP。
P2 · 2–4w
真正的 control planecreate/focus/rename/split/move/close pane、agent prompt/wait/read、Persistent Terminal 建立流程、workspace canonical-path binding、明確 destructive confirmations。
P3 · later
Worktree 與 remote先做 worktree list/open/create；remove 必須整合 Yuzora open-workspace/unsaved/git guards。Remote 初期只提供 Herdr TUI in SSH terminal；透明 remote API proxy 另立專案。

估算解讀：若目標只是「在 Yuzora 看與控制現有 Herdr panes」，約 2–3 週可達 production beta；若要完整 workspace/worktree/remote 與跨平台 hardened，應預留 5–9 週，且 Windows named pipe、controller ownership、server upgrade/reconnect 會是主要成本。

風險與緩解

Protocol drift
Raw API 雖有 schema，但 client/server protocol mismatch 會直接失敗。啟動先 ping，只接受測試過的 protocol 範圍；未知欄位忽略；升級／live handoff 後自動 reconnect＋resnapshot。
Controller takeover
一個 terminal 只能有一個 writable controller。Yuzora 不可自動 --takeover；衝突時降級為 observer，顯示「取得控制權」按鈕與風險說明。
Secret exposure
Terminal frames、pane reads、history 可能含 token、prompt、路徑。預設不持久化 frame／scrollback、不寫一般 log；diagnostic 僅記 metadata。Herdr 自己也因同一風險把 pane history 預設關閉。
Plugin trust
Herdr plugin 是以使用者權限執行的普通程式碼，無 sandbox。Yuzora 初期不要提供 marketplace 一鍵安裝；若未來提供，必須顯示 source/ref/build/runtime commands 並要求明確確認。
Binary trust/update
從 PATH 執行可能命中非預期 binary。設定中顯示 absolute path/version/channel；記住使用者批准的 binary identity。若 bundle sidecar，需處理 Apache NOTICE、多平台 artifacts、Herdr 自身 updater 與 Yuzora updater 的責任分界。
Duplicate workspace truth
Yuzora 與 Herdr 都有 workspace/tab 概念。Herdr focus 不應無條件切 Yuzora workspace；只有已建立 canonical binding 且通過 unsaved guard 時才同步。
Worktree mutation
Herdr 可直接建立／移除 Git worktree，而 Yuzora Git/Editor 可能仍使用該 checkout。第一版只讀；第二版 create/open；remove/force 最後做，且永不自動。
Source availability
Apache-2.0 允許 fork/bundle，但「能 fork」不等於「應 fork」。直接依賴 Herdr internal Rust modules 會綁死其 app state、protocol、PTY/render internals，維護成本高於 sidecar。

Go / No-Go 決策門檻

Go：符合以下條件就值得立項

  1. 接受 Herdr 與 ACP 是兩條並存 runtime，而不是把所有 agent 統一成一種 session。
  2. 第一階段聚焦 local Herdr；remote/worktree mutation 延後。
  3. Rust backend 掌握 socket與process bridge，React 不直接連 filesystem socket。
  4. 預設 observer，不搶 controller；所有 destructive action 有明確確認。
  5. Herdr server/panes 在 Yuzora 關閉時繼續存活，Yuzora 只 release 自己的 attachment。

No-Go：若需求是以下任一項，應停止或重寫目標

  • 要求 Herdr 無損取代 AgentZone 的 ACP rich transcript 與 permission/edit integration。
  • 要求同一個 ACP adapter process 同時由 Yuzora pipe stdio 與 Herdr PTY 擁有。
  • 第一版就要求 1:1 複製 Herdr 全部 BSP layout、remote、plugin、worktree mutation。
  • 要求把 Herdr 直接編譯成 Yuzora 內部 library 並跟隨其 private APIs。
最終建議：立項，但專案名稱應是「Herdr Persistent Runtime Integration」，不是「Herdr replaces Yuzora Agent/Terminal architecture」。
