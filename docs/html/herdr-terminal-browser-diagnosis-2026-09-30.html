3. Fullscreen 捲動：先確認誰擁有歷史

普通 shell 的歷史由 HERDR host scrollback 保存；fullscreen TUI 的對話歷史通常由應用程式自己管理。xterm 的 alternate buffer 也不會因為調高一般 scrollback 就保存完整 TUI 歷史。本次以真 xterm 6 寫入 30 行、8-row viewport：normal buffer 長度 30、baseY=22；alternate buffer 長度只有 8、baseY=0。xterm buffer API 將 normal 與 alternate 明確分開。

權威 child 狀態官方 HERDR wheel 行為Yuzora 應遵循的語意
Mouse tracking 開啟向 child 發送 mouse wheel report即使 host 有歷史，也應優先送給 TUI
Alternate screen + alternate-scroll依官方規則送方向鍵由 HERDR 判斷與編碼，不從外層 xterm 猜
其餘捲 host viewport由 HERDR scroll range 驅動 scrollbar

官方依據：wheel routing、server input dispatch。

目前工作樹已經做了什麼

terminalTransport.ts:459–472、519–556 已有未提交補強：當 hostRange=0／null 且 capability 允許時改走 application wheel；保留 pointer cell，對連續 wheel 做節奏控制。這些修改不是本次分析新增的修正。使用者正在執行的 build 若未包含它們，舊的零 range host-scroll 路徑足以解釋失效。

但 current router 在 hostRange>0 時仍直接選 pane.scroll，這不能涵蓋「normal buffer、有歷史、同時開 mouse tracking」的 TUI。HerdrTerminalPage.tsx:916 又以外層 alternate 狀態決定是否放行 xterm；由於 connector 沒保證映射 child modes，不能以這個分支作為 child fullscreen 的權威判斷。

修正方向：將實體 wheel 的應用程式／host 路由交由 HERDR 的 child-mode-aware 操作決定；scrollbar 拖曳則保持明確的 host absolute scroll。若當前版本／能力不支援，應保留清楚的相容性 fallback。不要增加假的 scroll range，也不要把 xterm 的重繪垃圾當成會話歷史。

驗收矩陣應涵蓋 Claude／Codex fullscreen、normal-buffer mouse TUI、有／無 host history、touchpad／wheel、macOS／Windows／WSL、observe 模式與 capability rejection。成功條件是 TUI 內容移動且不意外改動 shell host viewport；實際使用者的 CLI 版本及畫面模式仍待確認。

跨工作區需要處理資源 ownership

previewStore.ts:9、407 只保存 URL、URL history、frame 與 reloadNonce；保存 URL 無法保留 JS heap、表單與連線。workspaceStore.ts:458 清除非 HERDR tabs，SessionRestoreBridge.tsx:184 排除 preview persistence。

此外，useRemotePreviewUrl.ts:47 在 unmount 釋放 tunnel；filePreview.ts:141 在 workspace switch 清 lease。Rust 目前只有固定 preview-child，新 session 會 close 舊 child；preview_resources.rs:81 只有一個 active resource。因此不能只在 React 多掛幾個 PreviewPanel 就宣稱跨 workspace 已保留。

  1. 先修同工作區切 tab：Browser tab 存在即保持其 runtime 與 tunnel；inactive 只 hide，不 close、不 navigate。真正 close tab 才銷毀。visible 必須綜合 active tab、mode、overlay，避免 native layer 覆蓋其他畫面。
  2. 再修跨工作區：穩定 owner 為 {hostId, canonical workspace identity, browserTabId}；group 是顯示位置，搬 group 不改 identity。Rust 按 Browser ID 管理 webview；bounds、visibility、close、poll 皆帶 owner。
  3. 讓資源跟隨 Browser runtime：tunnel／HTML capability lease 隨 session 保存，明確 close、disconnect 或 generation 失效才釋放；保留 stale-response 與 workspace 安全檢查。

Browser session 的保留也需要有界資源政策，但不應以任意 tab deactivation 當作銷毀點；資源上限與回收提示可在跨工作區方案時明確決策。

最快的路徑是先把既有一般 pane 做成可靠 projector，再讓已有的官方 client 成為可持續切換的工作面。完整自行重做 HERDR client，會同時承擔輸入模式、copy/search、layout、graphics、popup 與版本同步成本。

建議執行順序與驗收

  1. Renderer 與 wheel contract：no-wrap＋grapheme parity；保留 synchronized frame 與尺寸防護；把 child-aware wheel 路由對齊官方。
    驗收：右下 ASCII/CJK/combining/ZWJ/VS16 matrix、full→delta、resize、hidden→visible，以及實際兩款 TUI 的捲動。
  2. 同 workspace Browser continuity：tab inactive 只 hide、close tab 才 dispose；tunnel 跟 Browser 存活。
    驗收：切 tab 前後 bootId、draft、scroll、JS／WebSocket session 不變；明確 close/reopen 才換實例。
  3. Astra trace 驅動修正：先錄得現場 frame／metrics，再依上一節四組對照定位。
