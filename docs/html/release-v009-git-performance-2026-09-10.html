v0.0.9 Git 載入效能驗證

2026-09-10 · release/v0.0.9 · Draft PR #94

使用者於 UI 修正 c52b655 後回報 Git 載入慢，特別是 git-diff。本次降低原生 Git 查詢的程序數，涵蓋狀態、分支／標籤、工作區差異及歷史檔案讀取。未改變跨主機路由、信任檢查、操作鎖、取消／逾時及輸出大小限制，也未引入 worktree 內容快取。

量測結果

macOS arm64、本機 Yuzora repository、同一個 Rust debug benchmark、每項連續讀取 5 次取平均。差異檔案使用 src/editor/editor.css。毫秒數是本機量測，不代表 Windows 安裝後的實測速度；Git 程序數由共用 runner 的 logger 計數。

讀取路徑平均耗時：修改前 → 後Git 程序：修改前 → 後
狀態刷新81 → 55ms3 → 2
分支／remote／標籤列表69 → 26ms3 → 1
工作區 diff46 → 25ms2 → 1
暫存 diff97 → 50ms4 → 2
單一歷史版本檔案75 → 49ms3 → 2

另以本機 Chromium Demo 將 Git IPC 替換為固定資料，單獨量測現有分割 diff 顯示：200／2,000／10,000 行約 46／41／60ms。這個結果只用於區分顯示與原生資料取得成本，不包含 Windows WebView2、SSH 或 WSL 延遲。本次沒有據此修改 CodeMirror 的演算法或隱藏部分差異。

修正與正確性

  • 工作區 diff 直接使用 git show 的結果與既有錯誤分類，移除每份內容前的 cat-file 存在性查詢；保留 staged、rename、unmerged 的 stage 1／stage 2／HEAD fallback。
  • 一次 for-each-ref 取得 heads、remotes、tags，依完整 ref namespace 分類；保留 current、upstream、ahead／behind／gone、tag creator date 與 remote HEAD 過濾。
  • status 只解析工作樹的 git-dir 以判斷 merge／rebase 等進行中狀態；需要 common-dir 的其他用途繼續走原 metadata_dirs。
  • 歷史讀取仍先驗證 revision，成功路徑直接讀內容；show 失敗時才以 literal、NUL-delimited ls-tree 確認 path 是否不存在。不存在回 Missing，損壞或不可讀物件維持錯誤，允許重試。

回歸測試

新增 Host integration fixture：建立原始、已暫存與工作區三份不同內容，驗證三方內容正確；同時檢查 local／remote refs、輕量與 annotated tags，並限制每次讀取的 Git 程序數。測試於修改前失敗，修改後通過；不以容易受機器負載影響的毫秒門檻作為 CI gate。

cargo test --locked --manifest-path src-tauri/host/Cargo.toml --test git_read_efficiency

修改前程序數為 (3, 3, 2, 4)，目標為 (2, 1, 1, 2)；歷史檔案讀取另由 3 降到 2。Host 完整測試 369 unit + 12 integration 通過，Host strict Clippy 通過；桌面 Git service 71 項測試通過，完整桌面測試 368 unit + 1 integration 通過（4 ignored），exact Clippy baseline 符合 90 diagnostics。

原始量測、負向測試輸出與 benchmark source 保留於本機 output/release-v0.0.9/git-*。前一版 UI 的瀏覽器驗證另見 UI 修正報告。最終候選安裝檔須來自包含本次修正的新 commit；c52b655 候選不包含此效能修正。
